# Rele

Локальное приложение, которое связывает Telegram и Slack с общими разговорами Codex. Контекст хранит Codex; ответ и запрос подтверждения возвращаются в источник конкретного запроса.

## Целевой сценарий

- Windows: Rele, codex app-server и Codex Desktop на одном ПК.
- Ubuntu Server: Rele, codex app-server и Codex CLI на одном сервере.
- Одна связка: один тред Codex, максимум один разговор Telegram и один тред Slack.
- Общий контекст Codex; каждый ответ возвращается в источник своего запроса.
- Веб-панель показывает связи по названиям.

WSL и отдельный компонент Rele Node исключены из первого релиза.

## Выпуск

**v0.1.0-rc.2 — release candidate.** Native Windows x64 и Ubuntu Server x64, одна кодовая база и один веб-интерфейс. Проверяемый протокол: **Codex app-server 0.163.0**. Другие версии отображаются в панели, но запись блокируется до проверки адаптера. Версия установленного CLI и версия сервера Desktop могут различаться.

В этом кандидате появился [каталог разговоров](docs/CATALOG.md): каналы и обсуждения Slack загружаются через API; Telegram предлагает обнаруженные чаты, выбор группы у бота и регистрацию темы; Codex показывает сохранённые разговоры с поиском и просмотром архива. Telegram подключается только токеном бота.

Общая история, очередь, восстановление и подтверждения проверяются на настоящем Codex с локальным тестовым inference provider. Это не заменяет приёмку настоящего Windows Desktop и разрешённых Telegram / Slack чатов. Условия стабильного релиза: [план](docs/PLAN.md), [приёмка](docs/ACCEPTANCE.md), [issue #2](https://github.com/smart-tinker/rele/issues/2).

## Быстрый запуск

Скачайте архив из [GitHub Releases](https://github.com/smart-tinker/rele/releases), проверьте SHA-256 и распакуйте его в постоянный каталог. Node.js 24.19.0 и production-зависимости входят в пакет. Codex, Python и модель распознавания устанавливаются отдельно.

Windows PowerShell:

```powershell
.\start-rele.cmd
```

Во втором терминале получите ключ панели:

```powershell
.\start-rele.cmd token
```

Откройте `http://127.0.0.1:3210` и введите ключ. Rele и Codex должны работать под тем же Windows-пользователем, что и Desktop.

### Если Windows не запускает `start-rele.cmd`

При сообщении «Системе не удается найти указанный путь» проверьте файлы из каталога распакованного Windows-выпуска:

```powershell
Test-Path -LiteralPath '.\runtime\node.exe' -PathType Leaf
Test-Path -LiteralPath '.\dist\server\main.js' -PathType Leaf
```

Если обе проверки вернули `True`, приложение можно запустить напрямую из PowerShell:

```powershell
& '.\runtime\node.exe' '.\dist\server\main.js'
```

Оставьте это окно открытым. Во втором PowerShell перейдите в тот же каталог и получите ключ панели:

```powershell
& '.\runtime\node.exe' '.\dist\server\main.js' token
```

Если прямой запуск работает, для диагностики `.cmd` сохраните вывод следующих команд из второго окна:

```powershell
& "$env:SystemRoot\System32\cmd.exe" /d /e:on /v:off /c '.\start-rele.cmd --version'
Get-Content -LiteralPath '.\start-rele.cmd'
```

Первая команда проверяет launcher с параметрами командного интерпретатора, заданными только для этого процесса. Она должна вывести версию Rele. [Значение параметров cmd](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd). Если хотя бы одного файла нет, заново распакуйте полный Windows ZIP в отдельный каталог и проверьте его содержимое.

### Ubuntu Server

```bash
./start-rele.sh
./start-rele.sh token
```

Панель слушает только loopback. Для доступа с рабочего компьютера используйте SSH-туннель:

```bash
ssh -L 3210:127.0.0.1:3210 user@server
```

После этого откройте `http://127.0.0.1:3210` на рабочем компьютере. Codex CLI, app-server и Rele остаются на Ubuntu Server.

## Подключение Codex

Режим **proxy** присоединяется к существующему локальному runtime. Укажите путь к Codex CLI; стандартный npm shim Windows поддерживается. Если сервера нет, Rele сообщает об этом и не создаёт отдельный daemon.

Для явного общего runtime на Ubuntu Server:

```bash
codex app-server --listen ws://127.0.0.1:4500
```

В другом терминале подключите CLI к тому же адресу:

```bash
codex --remote ws://127.0.0.1:4500
```

В Rele выберите WebSocket и `ws://127.0.0.1:4500`. При необходимости задайте bearer token в закрытом поле настроек. Используйте одного пользователя, нужный профиль Codex и доступный рабочий каталог. Внешние адреса app-server запрещены.

На Windows сначала проверяется соединение именно с runtime установленного Desktop. Общая папка истории не доказывает общий активный сервер. При несовпадении версий не следует создавать независимый daemon и считать его тем же разговором.

## Создание связки

1. Подключите Telegram и / или Slack Socket Mode в разделе «Подключения». [Настройка мессенджеров](docs/CHANNELS.md).
2. Откройте «Связки» → «Новая связка» и выберите существующий разговор Codex по названию и рабочему каталогу.
3. Для Slack выберите канал или личный диалог, затем обсуждение из загруженной истории. Для Telegram выберите обнаруженный чат и тему; отсутствующую группу можно выбрать через кнопку у бота, а тему зарегистрировать командой из панели.
4. Отметьте разрешённых отправителей по именам и создайте связку. Если участника нет в списке Telegram, попросите его выполнить команду регистрации именно в связываемой теме или чате. Для Slack список участников загружается через API.
5. Отправьте новое сообщение. Ответ вернётся в источник, следующий запрос из другой стороны продолжит контекст того же треда.

До связки и разрешения отправителя сообщения не запускают Codex. Чтение каталога, загрузка истории Slack и команды регистрации Telegram также не запускают Codex. Старые события не выполняются задним числом. Пустой список разрешённых отправителей запрещает выполнение.

Пауза останавливает приём новых задач и запуск ещё не начатых. Уже начатое выполнение продолжается до завершения или явной отмены. Если сервис не сообщает название старой темы, задайте локальное название в форме связки.

## Надёжность

- Входящее событие записывается в SQLite до подтверждения мессенджеру. Повтор не создаёт второй запрос.
- Постоянный UUID запроса сохраняется в `clientUserMessageId` Codex.
- `thread/queue/add` создаёт отдельный ход занятого треда. Rele не использует `turn/start` для отправки: этот метод может вмешаться в текущий ход.
- Потерянное подтверждение постановки вызывает сверку очереди и истории. Повтор `queue/add` с тем же UUID не идемпотентен и автоматически не выполняется.
- Финал и исходящие части ответа записываются одной транзакцией. Части доставляются по порядку.
- Явный отказ допускает повтор. Потерянное подтверждение отправки отображается как неопределённая доставка и автоматически не повторяется.
- Вмешательство Desktop в активный ход Rele блокирует внешнюю отправку смешанного ответа. Этот запрет сохраняется после перезапуска.

Прямые ходы Desktop / CLI не пересылаются в мессенджеры. Общий контекст включает обычное сжатие истории самим Codex. Маршрутизация ответа не создаёт изолированные контексты для Slack и Telegram.

## Голосовые

Аудио распознаётся локальным `faster-whisper`, в Codex отправляется текст. Модель устанавливается заранее; автоматическая загрузка при обработке сообщения запрещена. Функция выключена до настройки. Максимум 20 МиБ, до 10 минут обработки. [Установка и проверка](docs/VOICE.md).

## Данные и эксплуатация

- Windows: `%LOCALAPPDATA%\Rele`; секреты защищены DPAPI текущего пользователя.
- Ubuntu Server: `$XDG_STATE_HOME/rele` или `~/.local/state/rele`; каталог закрыт правами пользователя, конфигурация имеет режим `0600`.
- `RELE_DATA_DIR` задаёт каталог данных, `RELE_PORT` — loopback-порт.
- Ключ панели хранится в `sessionStorage` текущей вкладки и не передаётся в URL запросов API.

Windows: `install-autostart.cmd`. Ubuntu Server: `install-user-service.sh`. Остановка, автозапуск, резервные копии и обновление: [эксплуатация](docs/OPERATIONS.md).

## Разработка

Требуется Node.js **24.19.0** и npm:

```bash
npm ci
npm run typecheck
npm test
npm run build
npm start
```

Для разработки интерфейса запустите `npm run dev` и `npm run dev:web` в разных терминалах. Браузерные проверки:

```bash
npx playwright install chromium
npm run test:e2e
```

`npm run probe:codex -- --help` описывает проверку существующего runtime. `scripts/protocol-probe.py` использует отдельный профиль и локальный тестовый provider без пользовательских ключей. CI проверяет и собирает приложение на обеих ОС. Автопубликация допускает только версии `-rc.N`; стабильный выпуск требует приёмки.

Архитектурные решения: [ARCHITECTURE.md](docs/ARCHITECTURE.md).
