# План первого релиза Rele

Цель: v0.1.0 для нативной Windows и Ubuntu Server. WSL, отдельный Rele Node и распределённая установка исключены.

| Этап | Состояние | Критерий |
| --- | --- | --- |
| 1 Репозиторий и Codex | В работе | Атомарная очередь; общий runtime с CLI и настоящий прогон Desktop |
| 2 Локальное ядро | В работе | Сохраняемые связки, очередь, неизменяемый origin и восстановление |
| 3 Telegram и Slack | Ожидает | Общий контекст, ответ только инициатору, настоящие тестовые чаты |
| 4 Веб-панель | В работе | Создание связки по названиям, статусы и управляющие действия |
| 5 Надёжность и голосовые | Ожидает | Проверки сбоев; локальное распознавание аудио |
| 6 Установка | Ожидает | Пакеты, автозапуск, обновление и восстановление обеих ОС |
| 7 Выпуск | Ожидает | Проверенный кандидат; реальные интеграции; воспроизводимый тег и пакеты |

## Релизные условия

- Не использовать turn/start как замену атомарному запуску: он может steer текущий ход.
- Использовать thread/queue/add и thread/queue/start только после проверки поддержки; clientUserMessageId соответствует UUID запроса Rele.
- Не создавать скрытый независимый app-server при ошибке подключения к общему runtime.
- Не объявлять Desktop совместимым без реального прогона установленного клиента.
- Не перезапускать задачу с неопределённым результатом и не скрывать неопределённую доставку.
- Не считать тестовые doubles проверкой настоящих Telegram, Slack или Desktop.

## Требуемые внешние проверки

Для завершения стабильного выпуска нужны авторизованные тестовые Codex, Telegram и Slack, а также Windows с Desktop. Пока этих сред нет в рабочей сессии, выполняются реализация, локальные/CI проверки и подготовка воспроизводимого кандидата.
