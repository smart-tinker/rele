# Подключение мессенджеров

Одна установка Rele использует одного Telegram-бота и одну Slack-инсталляцию. Для двух независимо работающих машин создайте отдельные подключения. Не запускайте два consumer для тех же токенов.

## Telegram

Создайте бота через официальный BotFather и вставьте bot token в закрытое поле Rele. Включите Telegram и сохраните настройки. Rele использует `getUpdates` с long polling; публичный webhook или открытый входящий порт не нужен.

Если уже настроен webhook, Rele остановит подключение с объяснением. Чужой webhook не удаляется автоматически. Освободите выделенного бота от прежней интеграции перед подключением.

Для личного разговора откройте бота и нажмите Start. Для группы добавьте бота и настройте доступ к сообщениям через BotFather. При включённом privacy mode бот не видит произвольные сообщения группы. Для forum-групп связкой служит тема, для обычной группы или личного разговора — чат целиком.

В форме связки откройте «Выбрать группу в Telegram». Ссылка ведёт в личку бота, где кнопка открывает встроенный выбор группы, в которой бот уже состоит. Rele проверяет доступ, сохраняет название и показывает группу в каталоге. Личные чаты и темы обнаруживаются по доступным боту сообщениям; полный список старых чатов и тем Bot API не предоставляет.

Чтобы добавить ещё неизвестную тему, выполните в ней `/rele_register`. Можно добавить название после пробела, например `/rele_register Мониторинг`. Если в группе бот не отвечает, используйте адресную команду `/rele_register@ИмяБота`, показанную панелью: при privacy mode короткую команду может получить другой бот. Rele принимает обе формы, а команды с именем другого бота игнорирует. Команда только регистрирует разговор и отправителя, даже если для этого чата уже есть связка. Затем выберите разговор и разрешите отправителя по имени. События до связки не запускаются задним числом. Подробности: [каталог и создание связки](CATALOG.md).

Rele сохраняет названия групп и тем между перезапусками. События создания и переименования тем обновляют названия; локальная подпись в панели имеет приоритет. Удалённый из группы или заблокированный бот отмечает соответствующие известные разговоры недоступными.

Подтверждение команды или записи файлов приходит с кнопками. Выполнить его может только инициатор запроса из той же темы. Один обычный вопрос Codex завершается ответом на сообщение бота. Несколько вопросов и секретные поля заполняются в локальной панели.

Источники: [Bot API](https://core.telegram.org/bots/api), [FAQ о получении сообщений](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Slack

Создайте Slack app из [manifest](../integrations/slack-manifest.json) в нужном workspace. Включите Socket Mode. Создайте app-level token с разрешением `connections:write`, установите приложение в workspace для получения bot token.

В Rele нужны оба значения: bot token `xoxb-...` и app token `xapp-...`, относящиеся к одной Slack app. Не используйте пользовательский токен вместо bot token.

Manifest подписывает приложение на `app_mention`, `message.channels`, `message.groups`, `message.im`, `message.mpim`. Чтение каналов, истории и участников нужно для событий и названий; `chat:write` — для ответа; `files:read` — для голосовых. Неиспользуемые типы разговоров можно убрать вместе с соответствующими scopes и events.

Пригласите бота в канал. В форме связки Rele загрузит доступные боту каналы, личные и групповые диалоги. Выберите разговор, затем существующее корневое сообщение из истории и разрешённых участников. Предварительное новое сообщение в каждом обсуждении не требуется. Обычное корневое сообщение без ответов тоже может стать началом треда; два корня одного канала — разные обсуждения.

Каталог, история и участники загружаются постранично. Поиск в панели относится к уже загруженным вариантам; для более старых записей используйте «Загрузить ещё». Чтение истории не создаёт запросов Codex. Видимость ограничена членством бота, scopes, сохранённой историей workspace и лимитами Slack API. При отказе по scopes проверьте разрешения и переустановите приложение с актуальным manifest.

Повторные `message` и `app_mention` объединяются по каналу и timestamp сообщения. Все доступные сообщения связанного треда, включая других ботов, собственные ответы и наблюдённые правки/удаления, сохраняются как контекст. Для запуска отметьте отправителя в связке; другому боту дополнительно нужно новое прямое упоминание Rele. Цитата, код, старое упоминание в правке и пересылаемое вложение не запускают задачу.

Для полного контекста выберите режим Codex «Сервер Rele». В настройках связки откройте «Журнал контекста Slack»: там видны исходные сообщения, загрузка истории, передача и ошибки. Старая история загружается целиком постранично, без запуска задач. Во время чужого/активного хода контекст ждёт, затем переносится в простое. Пассивные записи доступны модели, но не отображаются отдельными сообщениями Desktop. При обрыве пассивная цитата может повториться; задачи с неизвестным результатом не отправляются повторно автоматически.

Во время работы используется штатный индикатор Slack через `assistant.threads.setStatus` (scope `chat:write`), с периодическим продлением и очисткой. Rich-ответы передаются native Markdown blocks: заголовки, списки, код, ссылки и таблицы. Длинные таблицы делятся с заголовком; превышающие ограничения сетки строки отображаются кодом. Сообщения Codex с локальными ссылками на файлы получают читаемый путь вместо служебной директивы.

История ограничена сохранёнными и доступными боту данными Slack: уже исчезнувшие сообщения невозможно получить задним числом. Сохраняются текст, blocks, attachments и metadata файлов; содержимое произвольных файлов автоматически не скачивается.

Slack не требует отдельного названия у треда. В каталоге Rele использует начало корневого сообщения, канал, дату и число ответов. Обсуждения, обнаруженные по входящим событиям, доступны и в сохранённом списке. Название можно заменить локальной подписью.

Подтверждения приходят с кнопками в исходный тред. Один обычный вопрос можно завершить следующим текстом в том же треде от исходного отправителя. Пока вопрос открыт, такое сообщение считается ответом на уточнение. Для нескольких вопросов и секретных полей используется панель.

Источники: [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/), [app token](https://docs.slack.dev/reference/methods/apps.connections.open/), [users.conversations](https://docs.slack.dev/reference/methods/users.conversations/), [conversations.history](https://docs.slack.dev/reference/methods/conversations.history/), [conversations.members](https://docs.slack.dev/reference/methods/conversations.members/), [conversations.replies](https://docs.slack.dev/reference/methods/conversations.replies/), [native Markdown](https://docs.slack.dev/reference/block-kit/blocks/markdown-block/), [индикатор работы](https://docs.slack.dev/reference/methods/assistant.threads.setStatus/).

## Смена токенов

Пустое поле секрета оставляет прежнее значение. Выключение подключения прекращает работу адаптера. При смене бота старый ответ не отправляется через нового бота: проверяется account identity.

Разрешённые отправители управляют запуском новых задач. Адрес уже принятого запроса неизменяем: изменение связки не перенаправляет старый ответ в новый чат.
