# Подключение мессенджеров

Одна установка Rele использует одного Telegram-бота и одну Slack-инсталляцию. Для двух независимо работающих машин создайте отдельные подключения. Не запускайте два consumer для тех же токенов.

## Telegram

Создайте бота через официальный BotFather и вставьте bot token в закрытое поле Rele. Включите Telegram и сохраните настройки. Rele использует `getUpdates` с long polling; публичный webhook или открытый входящий порт не нужен.

Если уже настроен webhook, Rele остановит подключение с объяснением. Чужой webhook не удаляется автоматически. Освободите выделенного бота от прежней интеграции перед подключением.

Для личного разговора откройте бота и нажмите Start. Для группы добавьте бота и настройте доступ к сообщениям через BotFather. При включённом privacy mode бот не видит произвольные сообщения группы. Для forum-групп связкой служит тема, для обычной группы или личного разговора — чат целиком.

В форме связки откройте «Выбрать группу в Telegram». Ссылка ведёт в личку бота, где кнопка открывает встроенный выбор группы, в которой бот уже состоит. Rele проверяет доступ, сохраняет название и показывает группу в каталоге. Личные чаты и темы обнаруживаются по доступным боту сообщениям; полный список старых чатов и тем Bot API не предоставляет.

Чтобы добавить ещё неизвестную тему, выполните в ней `/rele_register`. Можно добавить название после пробела, например `/rele_register Мониторинг`. Если в группе бот не отвечает, используйте адресную команду `/rele_register@ИмяБота`, показанную панелью: при privacy mode короткую команду может получить другой бот. Rele принимает обе формы, а команды с именем другого бота игнорирует. Команда только регистрирует разговор и отправителя, даже если для этого чата уже есть связка. Затем выберите разговор и разрешите отправителя по имени. События до связки не запускаются задним числом. Подробности: [каталог и создание связки](CATALOG.md).

Rele сохраняет названия групп и тем между перезапусками. События создания и переименования тем обновляют названия; локальная подпись в панели имеет приоритет. Удалённый из группы или заблокированный бот отмечает соответствующие известные разговоры недоступными.

Подтверждение команды или записи файлов приходит с кнопками. Выполнить его может только инициатор запроса из той же темы. Один обычный вопрос Codex завершается ответом на сообщение бота. На несколько обычных вопросов ответьте на сообщение бота строками `1. ответ`, `2. ответ` по порядку. Секретные поля заполняются только в локальной панели. Отмена собственного запроса из его исходного чата или темы — `/rele_cancel`.

Источники: [Bot API](https://core.telegram.org/bots/api), [FAQ о получении сообщений](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Slack

Для новой Slack app используйте [manifest](../integrations/slack-manifest.json) в нужном workspace. Он объявляет Agent feature через `features.agent_view.agent_description`. Включите Socket Mode. Создайте app-level token с разрешением `connections:write`, установите приложение в workspace для получения bot token.

В Rele нужны оба значения: bot token `xoxb-...` и app token `xapp-...`, относящиеся к одной Slack app. Не используйте пользовательский токен вместо bot token.

Manifest подписывает приложение на `app_mention`, `message.channels`, `message.groups`, `message.im`, `message.mpim` и `agent_session_stopped`. Чтение каналов, истории и участников нужно для событий и названий; `chat:write` — для ответов, Agent Sessions и Stop; `assistant:write` — для Agent feature; `files:read` — для голосовых и изображений. Неиспользуемые типы разговоров можно убрать вместе с соответствующими scopes и events.

Для существующей Slack app не заменяйте manifest целиком: сохраните её текущие features, scopes и events, добавив необходимые разрешения и `agent_session_stopped`. Если `assistant_view` уже включён, сохраните его: переход на `agent_view` ради Stop не обязателен и не выполняется Rele автоматически. Такой переход меняет интерфейс приложения для пользователей и необратим; сначала изучите [правила миграции Slack](https://docs.slack.dev/ai/migrating-to-agent-messaging/).

Если существующий бот ещё не объявлен агентом, оператор один раз явно включает Agent feature в настройках Slack app, проверив выбранный messaging experience и изменения manifest. Одна замена метода статуса в Rele не заменяет эту настройку; добавление scope само по себе не обещает включение Agent feature. Новые приложения используют `agent_view`. При добавлении `assistant:write` или другого отсутствующего scope заново авторизуйте установку, подтвердив разрешения. Токены вводите только в закрытые поля Rele, не в сообщения чата или публичную диагностику.

Одного обновления Rele для штатного Stop недостаточно: нужна подписка `agent_session_stopped` в Event Subscriptions той же Slack app. При предупреждении `missing_agent_session_stopped_event_subscription` Rele показывает причину недоступности Stop, не прерывая задачу.

Пригласите бота в канал. В форме связки Rele загрузит доступные боту каналы, личные и групповые диалоги. Выберите разговор, затем существующее корневое сообщение из истории и разрешённых участников. Предварительное новое сообщение в каждом обсуждении не требуется. Обычное корневое сообщение без ответов тоже может стать началом треда; два корня одного канала — разные обсуждения.

Каталог, история и участники загружаются постранично. Поиск в панели относится к уже загруженным вариантам; для более старых записей используйте «Загрузить ещё». Чтение истории не создаёт запросов Codex. Видимость ограничена членством бота, scopes, сохранённой историей workspace и лимитами Slack API. При отказе по scopes проверьте разрешения и переустановите приложение с актуальным manifest.

Каталог загружает только типы чатов, на чтение которых выданы права: `channels:read`, `groups:read`, `im:read`, `mpim:read`. Отсутствие права для одного типа не скрывает остальные; панель предупреждает о частичном каталоге. Личный чат отображается по имени собеседника со стороны бота. Для автосоздания выберите его, рабочую папку и разрешённого человека, включите правило и отправьте новое сообщение.

Повторные `message` и `app_mention` объединяются по каналу и timestamp сообщения. Все доступные сообщения связанного треда, включая других ботов, собственные ответы и наблюдённые правки/удаления, сохраняются как контекст. Для запуска отметьте отправителя в связке; другому боту дополнительно нужно новое прямое упоминание подключённого агента. Выберите его настоящее имя из списка после `@` в Slack; имя подключённого агента может отличаться от Rele. Цитата, код, старое упоминание в правке и пересылаемое вложение не запускают задачу.

Для полного контекста используйте режим Codex «Сервер Rele» либо общий локальный proxy/WebSocket-сервер с тем же профилем и подтверждённой записью в native истории. В настройках связки откройте «Журнал контекста Slack»: там видны исходные сообщения, загрузка истории, передача и ошибки. Старая история загружается целиком постранично, без запуска задач. Во время чужого/активного хода контекст ждёт, затем переносится в простое. Пассивные записи доступны модели, но не отображаются отдельными сообщениями Desktop. Повторная загрузка того же исходного сообщения не создаёт новую версию из-за случайного Slack `block_id`. При обрыве Rele сверяет точную сохранённую квитанцию, включая старые эквивалентные доставки; задачи с неизвестным результатом не отправляются повторно автоматически.

Rele управляет Agent Sessions через `agents.sessions.setStatus`: выполнение и распознавание аудио — `processing`, ожидание подтверждения или ответа — `suspended`, очередь, подготовка, неопределённость и завершение — `active`. Статус периодически продлевается и явно переводится из `processing`; обычная отправка ответа сама его не очищает. Точный вид spinner в обычных Activity/Threads требует отдельной проверки настоящего Slack client и пока не подтверждён.

Штатный Stop передаёт `agent_session_stopped` как управляющее событие, без новой задачи модели или записи в Slack-транскрипт. Rele сначала сохраняет receipt, затем проверяет исходные account, channel, thread и автора запроса. Повтор не отменяет запрос дважды; запоздавший Stop не становится новой задачей и не отменяет более поздний или ещё только локально ожидающий запрос. Смешанный с другим клиентом Codex ход автоматически не прерывается. Для отмены собственного ожидающего запроса остаётся обычное сообщение `rele:cancel` в исходном треде.

Rich-ответы передаются native Markdown blocks: заголовки, списки, код, ссылки и таблицы. Длинные таблицы делятся с заголовком; превышающие ограничения сетки строки отображаются кодом. Сообщения Codex с локальными ссылками на файлы получают читаемый путь вместо служебной директивы.

В новом разрешённом запросе Rele передаёт в Codex до четырёх загруженных в Slack PNG, JPEG, GIF или WebP (до 2 МиБ суммарно). Можно отправить изображение без подписи. Если файл недоступен или превышает лимит, Rele сообщает об ошибке вместо запуска запроса без изображения. Пассивный контекст старых и неадресованных сообщений по-прежнему содержит только метаданные вложений.

История ограничена сохранёнными и доступными боту данными Slack: уже исчезнувшие сообщения невозможно получить задним числом. Сохраняются текст, blocks, attachments и metadata файлов; содержимое произвольных файлов автоматически не скачивается.

Slack не требует отдельного названия у треда. В каталоге Rele использует начало корневого сообщения, канал, дату и число ответов. Обсуждения, обнаруженные по входящим событиям, доступны и в сохранённом списке. Название можно заменить локальной подписью.

Подтверждения приходят с кнопками в исходный тред. Один обычный вопрос можно завершить следующим текстом в том же треде от исходного отправителя. Пока вопрос открыт, такое сообщение считается ответом на уточнение. На несколько обычных вопросов ответьте строками `1. ответ`, `2. ответ` по порядку; Rele принимает ответ только после доставки всех частей вопросов. Секретные поля заполняются в панели.

## Смена токенов

Меню сообщения «Управление Rele» открывает Status/Goal/Model для существующей
связи. Область модели — общий Codex-чат со следующих запросов. Настройка shortcut,
scope `commands`, квитанции и точные native ограничения описаны в
[управлении через Slack](SLACK-CONTROLS.md).

Пустое поле секрета оставляет прежнее значение. Выключение подключения прекращает работу адаптера. При смене бота старый ответ не отправляется через нового бота: проверяется account identity.

Разрешённые отправители управляют запуском новых задач. Адрес уже принятого запроса неизменяем: изменение связки не перенаправляет старый ответ в новый чат.
