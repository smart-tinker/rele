# Rele 0.1.0-rc.13

Общий штатный Codex вместо зависимости от разового WebSocket-порта. Новая установка выбирает «Общий Codex»: Rele использует native daemon текущего пользователя и профиля, а при его отсутствии запускает его. Установленная полная CLI-поставка Codex должна поддерживать daemon; один отдельно скопированный codex.exe недостаточен. Rele не скачивает Codex, не переносит авторизацию и не копирует разговоры.

## Переход с предыдущего RC

1. Установите новую версию Rele обычным установщиком; штатная резервная копия сохраняется.
2. Если ранее был выбран WebSocket, proxy или отдельный «Сервер Rele», откройте «Codex», выберите «Общий Codex» и сохраните настройки при отсутствии активных запросов. Явные старые подключения не заменяются молча. Выбранный профиль сохраните тем же.
3. Один раз полностью выйдите из Codex Desktop. Приватный stdio сервер работающего Desktop нельзя превратить в общий без выхода. Rele чужие процессы не завершает.
4. Откройте «Codex Desktop (общий Rele)» из меню Пуск. Этот запуск задаёт адаптер только новому процессу. Файлы адаптера хранятся неизменно в versioned каталоге данных Rele, поэтому открытый Desktop не блокирует замену файлов программы при следующем обновлении. Дополнительная интеграция установщика задаёт CODEX_CLI_PATH и CODEX_APP_SERVER_FORCE_CLI для будущих обычных запусков Desktop; конфликтующие чужие значения сохраняются, установщик показывает предупреждение. Перезапуск окон Explorer/другого родительского приложения иногда нужен для обновления их окружения; явный launcher исключает эту зависимость.

Адаптер переводит только framing Desktop NDJSON ↔ WebSocket через штатный app-server proxy. Его initialize, идентификаторы RPC и событий сохраняются. Профиль проверяется до передачи следующих запросов. Нового TCP listener нет: используется приватный control socket Codex. Неподдерживаемые параметры запуска Desktop отклоняются, а не теряются.

## Ubuntu Server и интерактивный CLI

Desktop не требуется. В .deb отдельные rele-codex.service и rele-codex.timer проверяют native singleton от того же владельца, вне cgroup rele.service. Остановка/обновление Rele не останавливает общий daemon. Таймер восстанавливает отсутствующий daemon; Rele переподключается и сверяет принятые запросы.

Для строгого подключения интерактивного CLI используйте `rele codex` либо `rele-codex`; исходный разговор открывается через `rele codex resume ID`. В Windows используйте пункт «Codex CLI (общий Rele)»; в переносимой версии — start-codex.cmd/start-codex.sh. Launcher передаёт штатному CLI явный --remote unix://... и не допускает незаметного embedded fallback.

Обычный интерактивный Codex CLI также умеет native daemon, но его собственный fallback зависит от версии. `codex exec` не поддерживает --remote в проверяемых версиях: автоматические exec-сессии нельзя считать ещё одним подключением к общему runtime. Адаптер отклоняет exec, чтобы не создавать отдельный runtime незаметно. Служебные команды, включая --version и генерацию схемы, передаются настоящему CLI.

## Восстановление и сохранность

- Shared daemon живёт в штатной package selection внутри CODEX_HOME, отдельно от заменяемых файлов Rele и версионированных Desktop binaries. Native lifecycle lock предотвращает двойной запуск. Rele не вызывает daemon stop/update при своём shutdown или удалении.
- Windows native daemon использует явный breakaway из внешнего Rele Job. Прежний приватный ProcessHost для отдельного managed режима сохраняет свой ограничивающий Job.
- После переподключения используются прежние thread ID, профиль и request UUID. Потерянное подтверждение enqueue не разрешает повторную отправку: выполняется сверка очереди и истории. Подтверждения, уточнения и отмена остаются привязаны к источнику запроса.
- Сохранённая политика shared не содержит обнаруженного временного адреса или versioned executable. Обновление Desktop не переключает уже работающий native daemon и не прерывает его задачи. Автоматический native package update не выполняется.
- Права, связи многие-к-одному, журнал, outbox и SQLite6 сохранены; новой миграции БД нет.

## Граница проверки

Протокол и native lifecycle проверяются изолированными fixtures с fake provider на Windows/Ubuntu, без пользовательских профилей, настоящей модели и сообщений. Синтетический stdio клиент проверяет адаптер Desktop, но не считается запуском настоящего GUI. Приёмка реального установленного Desktop, телефонных подтверждений и Slack Agent Stop/spinner остаётся отдельной. Stable пока не публикуется.

Проверяемые версии Codex: 0.163.0, 0.163.0-alpha.10.2 и 0.163.0-alpha.11; прочие версии не получают разрешение на запись до проверки.
