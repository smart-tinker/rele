# Rele 0.1.1-rc.13 — Windows sandbox owner-directory compatibility

Codex's Windows sandbox can grant its machine-local `CodexSandboxUsers` group
read and execute access to its working directory. When this is Rele's native
controller directory, the previous all-foreign-grants check refuses daemon
status and controller startup even though the original owner and native
process remain unchanged.

The two Windows controller guards recognize only that exact machine-local
sandbox group with the expected explicit read/execute/synchronize grant and
file/directory inheritance. The existing owner identity, protected DACL,
reparse refusal and marker/executable hashes remain required. Unknown trustees,
additional rights, write/modify/delete and permission or ownership changes stay
rejected. No filesystem ACL is edited and the sandbox stays enabled.

The exception is confined to existing controller directories containing native
owner metadata and helper executables. It allows the sandbox group to read
that metadata; credentials and conversation history do not belong there.
Previously published candidates retain their original bytes.

Validation must include both compiled Windows guards, the real sandbox-group
read grant, write/foreign/protection/reparse negatives, the complete frozen
Windows/Linux build gates and separate ready-package acceptance. The installed
native process, current authentication, profiles and business state must be
preserved. Source checks or publication alone do not establish GUI, recovery
or stable acceptance.
