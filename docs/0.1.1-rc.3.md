# Rele 0.1.1-rc.3

Refs #46.

A verified human can open and answer a question for their own app-assisted
message in the same private discussion. Previously Rele accepted such a DM
using its verified human roster, but the event's conservative bot-origin flag
then blocked the human at the question button. The original event remains
bot-authored. The exception requires the same exact sender ID, an explicit
verified-human actor, a verified nonbot entry in the immutable origin roster,
and the same account/chat/thread. Bot, unknown, other-person and other-source
control stays denied; existing group rules are unchanged.

Native and async question paths share the ownership check and both have
engine regressions. Unit/native results, frozen commit and package hashes
are recorded in the RC evidence, not inferred from compilation.

RC2 assets stay immutable. Ready-package acceptance is on Windows test host (Windows)
and Linux acceptance host (Linux); Linux builds run on Linux build host, with no build agent runtime test.
Telegram live acceptance is postponed by the owner. A real Desktop-host async
flow and final stable acceptance remain separate gates. No automatic stable
or fleet rollout is implied by this candidate.
