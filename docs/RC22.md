# Rele 0.1.0-rc.22

Сообщения из Slack и Telegram содержат фактического автора, признак человека или агента, источник и снимок известных участников именно этого треда на момент сообщения. Техническая роль `user` в Codex не означает, что автором был владелец аккаунта. Список участников может быть неполным; он не определяет адресатов. Исходные обращения, включая несколько упоминаний, сохраняются в тексте.

Короткая инструкция передаётся вместе с запросом. Привязка чата сама по себе не запускает Codex. Модель, reasoning, sandbox и политика подтверждений существующего разговора сохраняются.

Rele устанавливает собственный локальный плагин со скиллом и тремя инструментами: `list_destinations`, `send_message`, `get_message_status`. Они доступны и при работе из Desktop. Отправить сообщение можно в разрешённый источник, связанный с текущим Codex-тредом, с нулём, одним или несколькими явными упоминаниями известных участников. Произвольные внешние адреса не принимаются. Для упоминания нужен подтверждённый Slack user ID или Telegram username; неизвестное значение не угадывается.

Отправка имеет постоянную квитанцию и отображается в «Доставке». Потерянное подтверждение не вызывает слепого повтора: сначала проверяется состояние операции. Отзыв доступа, изменение связки или пауза до отправки отменяют её. Прямой ответ Desktop не рассылается автоматически; явный вызов `send_message` является отдельным действием. Получение сообщения другим агентом не доказывает принятие или выполнение задачи.

Если политика Codex требует подтверждения `send_message` во время запроса Rele, адресат и полный текст приходят в исходный чат. Человек может разрешить эту отправку один раз или отклонить её. Подтверждение не меняет политику разговора и не разрешает будущие отправки автоматически.

Точный успешный финальный ответ `NOREPLY` подавляет отправку ответа в мессенджер. Запрос завершается, индикатор работы снимается, решение видно в очереди. Этот маркер внутри обычного текста не действует; ошибки и подтверждения не скрываются, уже отправленные сообщения инструмента не отзываются. Решение прекратить бесполезный обмен принимает модель по инструкции, ограничения числа обменов нет. Защита от повторных событий и собственных исходящих сохраняется.

В разрешённых группах принимаются сообщения других агентов; для Telegram режим Bot-to-Bot должен быть включён в настройках бота. Личные сообщения остаются только для разрешённых людей. Для запроса агента Stop, подтверждение, отказ и ответ на уточнение разрешены проверенному человеку в исходном обсуждении этой группы. Агентам такое управление через текст не разрешено. Для запроса человека сохраняется прежняя проверка первоначального отправителя.

Журнал синхронизации доступен и для Telegram. Он отражает сообщения, наблюдавшиеся Rele; загрузка прежней истории Telegram не заявляется.

На Windows общий сервер получает стабильное локальное соединение со встроенными app-tools Desktop. Оно проверяет владельца, сеанс и пакет Desktop, передаёт протокол без изменений и заново находит Desktop после его перезапуска. Основное соединение Desktop с native app-server остаётся прямым WebSocket. Если Desktop закрыт, его инструменты недоступны; обычная работа общего Codex продолжается.

**Обновление:** если общий Codex уже работал, Rele сохраняет его вместе с задачами. Исправление app-tools вступит после следующего запуска обновлённого общего сервера или перезагрузки Windows. Перезапуска одного Desktop недостаточно. Перед перезагрузкой завершите текущие задачи.

База Rele получает отдельную таблицу исходящих операций (schema 7); прежние запросы и доставки не переписываются. Перед обновлением сохраняется штатная резервная копия. Для отката на старую версию нужна её совместимая резервная копия базы. История и хранилище Codex не мигрируют.

После удаления Rele его собственный плагин `rele@rele-local` остаётся в Codex: отключите или удалите его в списке Plugins. Пока приложение Rele отсутствует, этот инструмент недоступен. Остальные плагины и backend Desktop не подменяются.

Проверки точного commit и пакетов приводятся в GitHub release. Реальная доставка Slack/Telegram, внешний вид индикатора в боковом списке Slack и управление с телефона остаются отдельной пользовательской приёмкой. Ограничения экспериментального native API, локального WebSocket без токена и неподписанного Windows RC сохраняются.
