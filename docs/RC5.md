# Rele 0.1.0-rc.5

## Что исправлено

- Участники Slack загружаются через POST form для conversations.members и users.info. В живой проверке JSON давал invalid_arguments и user_not_found, а form с теми же параметрами успешно возвращал участников и имена. Остальные запросы и JSON-доставка сообщений сохраняют прежний формат; права отправителей не расширяются.
- Панель предлагает короткую `/rele_register [имя]`. Адресная форма `/rele_register@имя_бота [имя]` остаётся подсказкой для групп, где Telegram privacy routing не доставляет короткую команду нужному боту. Обе формы принимаются; чужой @бот игнорируется. Регистрация не запускает Codex.
- Каталог Codex запрашивает только обычные cli, vscode, exec и appServer треды. Guardian, review, compact и другие служебные субагенты исключаются по source/parent metadata. Пользовательский тред с названием Guardian review не скрывается.
- Первое открытие каталога читает индекс Codex без полного сканирования истории. Кнопка «Обновить разговоры» выполняет полное перечитывание старых неиндексированных записей. Архив остаётся доступен отдельно; просмотр не возобновляет разговор и не ставит задачи.

## Обновление

Установите Windows Setup или Debian-пакет поверх предыдущего кандидата. Данные, токены, связки и исходные ID Codex сохраняются, схема SQLite остаётся v3. После обновления откройте панель заново и обновите участников Slack.

При переходе с rc.3 сохранённый proxy/WebSocket не меняется автоматически: выберите «Сервер Rele» в настройках Codex. Проверенные версии протокола остаются 0.163.0 и 0.163.0-alpha.10.2. Полный контракт managed-режима и остановки дочернего процесса описан в [RC4.md](RC4.md).

## Проверки и границы

Регрессии проверяют фактические отказы Slack на JSON, имена и пагинацию участников, обе формы регистрации Telegram, фильтрацию типов Codex, быстрый и полный режимы каталога, а также отсутствие resume/enqueue при просмотре. Native Windows/Ubuntu CI выполняет установщики, протокольные и managed probes двух закреплённых версий, voice, браузерные проверки и production UI smoke.

Точные результаты соответствуют commit в GitHub Actions. Этот выпуск остаётся неподписанным release candidate. Реальные Windows Desktop/Telegram/Slack сценарии и переход между установленными кандидатами закрываются отдельно по [ACCEPTANCE.md](ACCEPTANCE.md); stable автоматически не публикуется.
