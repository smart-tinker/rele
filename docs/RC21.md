# Rele 0.1.0-rc.21

Страница «Связи» объединяет назначение Codex и доступ: **Группа/Чат — Тема/Обсуждение — Разговор Codex — Доступ**, с вкладками Telegram и Slack. Несколько источников могут использовать один разговор. Прежние ограничения отправителей сохраняются; новые источники выключены, в личных чатах допускаются только выбранные люди. Правила для новых обсуждений и журнал автосоздания находятся ниже таблицы. В текстовых фильтрах добавлена кнопка очистки с возвратом фокуса в поле.

При выборе разговора Rele сначала проверяет индекс Codex. Полный обход истории требуется только если выбранный старый разговор отсутствует в индексе. Проверки архивности, профиля и рабочей папки сохранены. Тайм-аут индекса не вызывает повторную отправку.

Фоновый Windows ProcessHost собирается без консольного окна. Обновление готовит новый неизменяемый host для будущего запуска той же задачи, сохраняя работающий общий Codex и его клиентов. Уже открытое консольное окно прежнего host обновление не закрывает: оно исчезнет после штатного завершения старого процесса. Проверка статуса не меняет настройки.

Восстановленная вкладка браузера поясняет вход через обычный ярлык Rele. Токен по-прежнему действует в текущей вкладке; схема авторизации не меняется.

При подтверждённой ошибке Codex `serverOverloaded` исходный канал получает понятную причину перегрузки. Неизвестные ошибки остаются общими: служебные сообщения, пути и секреты backend не пересылаются. Ошибка выполнения не означает ошибку доставки; автоматического повторения запроса нет, поскольку часть действий могла уже выполниться.

После завершённой ошибки Codex может сохранять у чата статус `systemError`. Rele проверяет завершённость последнего хода и пустую очередь, затем передаёт накопленный Slack-контекст и следующий разрешённый запрос. Прежний ошибочный ход не повторяется; активная задача и неподтверждённое состояние по-прежнему блокируют передачу.

Архитектура, профиль Codex и хранилище разговоров не меняются. Windows Desktop и Rele подключаются напрямую к одному локальному native WebSocket. Ограничения loopback без токена, экспериментального native API и неподписанного Windows RC сохраняются. Проверки точного commit и пакетов приводятся в GitHub release; реальные Slack/Telegram и длительная эксплуатация остаются отдельной пользовательской приёмкой.
