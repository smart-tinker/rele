# 0.1.1-rc.20

Состав кандидата для Windows x64 и Ubuntu Server x64. Эти заметки не подтверждают
наличие пакетов или их приёмку: доступность, точные SHA-256 и результаты проверок
определяются конкретным [GitHub Release](https://github.com/smart-tinker/rele/releases).

- Меню сообщения Slack открывает Статус / Цель / Модель. Goal читается, но создание и
  остановка из Slack отключены: поддерживаемый native API не даёт условно записать
  именно проверенную цель. Создание делает upsert, остановка меняет текущую цель; при
  гонке запись может затронуть другую цель. [Issue #1](https://github.com/smart-tinker/rele/issues/1)
  остаётся открытым для безопасной native-возможности и Slack Desktop/mobile приёмки.
  Rele остаётся персональным workspace; новые роли и списки операторов не добавляются.
- Модель и reasoning effort меняются для общего Codex-чата со следующих запросов.
  Активный ход сохраняет настройки; каталог моделей не доказывает доступ провайдера.
- Ранее принятые native Goals в shared продолжают использовать штатные хронологические
  сообщения и сохраняемые квитанции. Потерянные события и ACK видны как неопределённость;
  слепого повторного запуска или отправки нет. Подробнее: [Slack controls](SLACK-CONTROLS.md).
- Вход в панель начинается со ссылки запуска; ручной токен остаётся резервным.
  Раздел и фильтр очереди сохраняются в URL, работают refresh и Back/Forward.
- Read-only трасса связывает приём, native execution и доставку по origin.
  Уведомление о повторе не считается доставленным итоговым ответом.
- Исправлены гонки повторов при перегрузке Codex, обновлены уязвимые зависимости.
  CI и регламент выпуска разделяют source, пакеты и установленную приёмку.

## Ограничения

Новый Goal в managed недоступен: первый запрос подтверждения может прийти раньше
доказуемой связи Goal с ходом. В shared такие подтверждения и безопасное управление
Goal доступны через native UI Codex; общая отмена этапа в очереди не заменяет
приостановку Goal. Reasoning, команды и чужой ввод в этапы не публикуются.

[Issue #26](https://github.com/smart-tinker/rele/issues/26) остаётся открытым по
историческому cleanup stage: исходный [Windows run #43375287426](https://github.com/smart-tinker/rele/actions/runs/43375287426)
сохранил только агрегированный `TimeoutError()` без точной операции, длительности
или процесса. Поздний [run #44227151928](https://github.com/smart-tinker/rele/actions/runs/44227151928)
отдельно записал `EngineDriver.read` timeout и ошибку `engine-close-ack` после
17,335 ms; это не устанавливает этап или причину исходного инцидента.

Проверки с изолированным loopback provider не подтверждают реальную Slack
desktop/mobile доставку, доступ модели у провайдера или Windows GUI/DPAPI в сессии
владельца. Готовые пакеты принимаются отдельно по [ACCEPTANCE](ACCEPTANCE.md).
Публичный RC, stable, Latest и rollout — разные переходы по [RELEASING](RELEASING.md).
