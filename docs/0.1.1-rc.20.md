# 0.1.1-rc.20

Состав кандидата для Windows x64 и Ubuntu Server x64. Эти заметки не подтверждают
наличие пакетов или их приёмку: доступность, точные SHA-256 и результаты проверок
определяются конкретным [GitHub Release](https://github.com/smart-tinker/rele/releases).

- Меню сообщения Slack открывает Статус / Цель / Модель. Rele остаётся персональным
  workspace; новые роли и списки операторов не добавляются.
- Модель и reasoning effort меняются для общего Codex-чата со следующих запросов.
  Активный ход сохраняет настройки; каталог моделей не доказывает доступ провайдера.
- Native Goal в shared использует штатный API, отдельные хронологические сообщения
  и сохраняемые квитанции. Потерянные события и ACK видны как неопределённость;
  слепого повторного запуска или отправки нет. Подробнее: [Slack controls](SLACK-CONTROLS.md).
- Вход в панель начинается со ссылки запуска; ручной токен остаётся резервным.
  Раздел и фильтр очереди сохраняются в URL, работают refresh и Back/Forward.
- Read-only трасса связывает приём, native execution и доставку по origin.
  Уведомление о повторе не считается доставленным итоговым ответом.
- Исправлены гонки повторов при перегрузке Codex, обновлены уязвимые зависимости.
  CI и регламент выпуска разделяют source, пакеты и установленную приёмку.

## Ограничения

Новый Goal в managed недоступен: первый запрос подтверждения может прийти раньше
доказуемой связи Goal с ходом. В shared такие подтверждения обрабатывает native UI
Codex. Остановка цели выполняется через её меню; общая отмена этапа в очереди
не заменяет приостановку Goal. Reasoning, команды и чужой ввод в этапы не публикуются.

Проверки с изолированным loopback provider не подтверждают реальную Slack
desktop/mobile доставку, доступ модели у провайдера или Windows GUI/DPAPI в сессии
владельца. Готовые пакеты принимаются отдельно по [ACCEPTANCE](ACCEPTANCE.md).
Публичный RC, stable, Latest и rollout — разные переходы по [RELEASING](RELEASING.md).
