# 0.1.1-rc.14 — Stop после перезапуска шлюза

Refs #78. Related #64 остаётся отдельной задачей индикатора занятости Slack.

В RC13 первый Stop после перезапуска Rele мог прервать собственный native-ход,
затем вернуть ошибку проверки команд и оставить запрос uncertain. Новый кандидат
сохраняет доказательство поколения native со снимком команд до запуска запроса.
После reconnect оно позволяет подтвердить прежний процесс и закончить отмену.
Проверка уже начатой до обрыва отмены остаётся отдельной: её потерянные действия
не повторяются автоматически.

Поколение связывается с фактическим локальным transport, временем запуска,
загрузкой ОС, исполняемым файлом, владельцем и исходным профилем Codex. Новое
подключение Rele и обновление контроллера будущего запуска не меняют это
доказательство, пока работает прежний native. Обычная сетевая активность других
задач не должна влиять на принадлежность проверяемого соединения.

Старые baseline без доказательства поколения остаются неопределёнными.
Свежий снимок не доказывает их прошлое: старый запрос не запускается повторно,
его metadata и история не переписываются. При смене/отсутствии подтверждённого
native или смешанном вводе автоматическое прерывание не отправляется.

Стандартные локальные shared/managed подключения Windows и Linux проверяются
отдельными тестами. Произвольный WebSocket и нестандартные wrapper-цепочки могут
не дать доказательства процесса; отмена в таком случае требует сверки. Поддержка
очереди сама по себе не означает подтверждения identity для очистки команд.

Проверки исходников, frozen сборки и приёмка готовых пакетов — отдельные этапы.
Windows собирается на windows-test-host, Linux — на linux-build-host. Ready packages устанавливаются
штатно и проверяются на windows-test-host/linux-test-host; native Codex, профиль, история и остальные
запросы сохраняются. Фактические commit, хеши и результаты публикуются в описании
RC после выполнения gates. GitHub Actions и Wine не используются.

Это кандидат, не приёмка stable. Опубликованный RC13 сохраняется.
