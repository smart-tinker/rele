# Rele 0.1.0-rc.16

Исправлен отказ обычного запуска Codex Desktop после обновления Rele с прежними явными настройками подключения. В rc.15 установщик мог включить адаптер Desktop при сохранённом WebSocket target и уже отсутствующем backend. Desktop преобразовывал отказ дочернего процесса в общее окно «Не удалось загрузить настройки организации».

Перед включением интеграции установщик теперь проверяет защищённые настройки Rele, общий режим, доступность поддерживаемого Codex и ранние read-only запросы Desktop: initialize, effective code_mode_host, configRequirements/read и config/read. Если проверка не проходит, hook Rele не включается; ранее включённый принадлежащий Rele hook снимается. Предупреждение объясняет причину, исходные конфигурация и профиль сохраняются. Чужие переменные окружения не заменяются.

Если во время установки работает прежний приватный Desktop, проверка откладывается только при подтверждённом shared-desktop-conflict. Установщик не останавливает Desktop: один раз полностью выйдите из него и откройте обычным способом. Неизвестный владелец процесса остаётся блокирующей ошибкой. Проверка выполняется снова при запуске адаптера. Явный launcher общего Desktop также проверяет ранние настройки перед открытием GUI.

Прежние явные managed/proxy/WebSocket подключения автоматически не меняются. После завершения запросов отключите интеграцию Desktop в установщике Rele, выберите «Общий Codex» с исходным профилем и снова включите интеграцию. Пока установщик считает интеграцию активной, смена сервера или профиля в панели блокируется до её отключения. Это не позволяет незаметно сломать следующий запуск Desktop. Новая установка уже использует общий режим; отдельный CLI на Windows не требуется.

Ошибки чтения защищённых настроек и отсутствующий выбранный executable имеют отдельные безопасные сообщения. Пути, содержимое настроек и native ошибки не копируются в Desktop. Приватный запасной сервер не запускается; thread/request IDs, очередь, SQLite v6 и native история не мигрируют. Ubuntu CLI/systemd схема сохранена. Новых зависимостей нет.

Debian-пакет задаёт публичным каталогам и файлам приложения корректные права независимо от umask сборщика. После установки от root служба выбранного пользователя может прочитать и запустить payload; приватные настройки пользователя этим не затрагиваются. Относительные ссылки внутри пакета сохраняются при переносе на другую машину.

Регрессионные проверки включают upgrade с прежним WebSocket target и удалённым executable, отказ DPAPI, сохранение конфигурации побайтно, снятие только собственного hook, отказ несовместимой смены настроек, ранние policy RPC через установленный адаптер и установку при живом приватном Desktop. Итоговые результаты фиксируются в PR и выпуске; native backend/stdio проверки не считаются проверкой GUI. Живой GUI/Explorer, телефон и reboot остаются открытой приёмкой.
