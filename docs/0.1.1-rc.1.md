# 0.1.1-rc.1 — вопросы Codex в Slack и сохранение контекста

Подготовлен общий release candidate для Windows и Ubuntu. Он ещё не опубликован
в GitHub; последний опубликованный выпуск — v0.1.0. После PR/main и публикации
готовое приложение проходит приёмку только на Windows test host (Windows) и Linux acceptance host (Linux).
Windows собирается на Windows test host,
Linux — на Linux build host, в изолированных build-каталогах, без Wine. Затем отдельный этап
приёмки проверяет готовые installers/portable и установленное приложение,
не запуская dev-suite. Linux acceptance host используется только для приёмки, без исходников
репозитория и dev-окружения. GitHub Actions не используется.
Issues закрываются после принятия их критериев на опубликованном RC.
Решение о stable и обновлении остальных машин принимается после приёмки;
стабильный 0.1.1 на этом этапе не выпускается. [Стандарт рабочего цикла](DEVELOPMENT.md),
[критерии приёмки](ACCEPTANCE.md).

Задачи выпуска: [#44 — async-вопросы](https://github.com/smart-tinker/rele/issues/44),
[#45 — длинные варианты](https://github.com/smart-tinker/rele/issues/45),
[#46 — роль человека](https://github.com/smart-tinker/rele/issues/46),
[#47 — объём истории](https://github.com/smart-tinker/rele/issues/47),
[#48 — ID контекста](https://github.com/smart-tinker/rele/issues/48).

- Асинхронные вопросы Codex Desktop и native-вопросы с вариантами ответа
  используют карточки и формы Slack. Ответ относится к исходному вопросу,
  треду и источнику запроса; вопрос, закрытый в Desktop, закрывается и в Slack.
- Выбранный вариант или собственный ответ передаётся точно. Карточка различает
  очередь, отправку, подтверждённый результат и неизвестный результат после
  сбоя. Потерянное подтверждение сверяется с историей Codex; автоматической
  повторной отправки такого ответа нет. Секретные ответы остаются в локальной
  панели Rele.
- Проверенная информация Slack о человеке исправляет ошибочную сохранённую
  отметку «бот». Неполные события сохраняют известную роль; служебный признак
  сообщения от приложения не переопределяет проверенный профиль отправителя.
- Длинные варианты ответа открываются в форме Slack: полный текст остаётся
  читаемым, короткие варианты доступны кнопками.
- Новые пассивные сообщения используют локальные ID `rele-context-…` без
  подчёркиваний. В проверенном Codex 0.166 этот ID остаётся в локальной истории,
  а провайдер получает сообщение без него. Старые ID и точные квитанции
  продолжают распознаваться; существующая история не переписывается.
- История запрашивается по одному ходу на страницу вместо 50, с последовательным
  обходом страниц. Это уменьшает размер каждого ответа с полной историей хода.
  Предел одного входящего WebSocket-сообщения — 32 МиБ.

Разговоры сохраняют исходные ID, профиль и историю. Полный контекст и сжатие
по-прежнему принадлежат Codex. Приёмка конкретных пакетов и обновления машин
подтверждаются отдельно от готовности исходников.
