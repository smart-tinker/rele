# Управление Rele из меню сообщения Slack

В меню non-ephemeral сообщения выберите «Управление Rele». Корень и любой
ответ одного треда адресуют одну существующую связь с Codex. Текст выбранного
сообщения не становится запросом. Если связи нет, она изменилась или текущая
учётная запись не совпала, форма показывает отказ; новый чат не создаётся.

Rele предназначен для персонального workspace. Используются существующие
правила доступа источника и подтверждённый человек Slack. Отдельных операторов,
ролей или списков разрешений управление не вводит. Участие в разговоре, account,
channel/thread, автор формы и связь проверяются при открытии и отправке.

## Настройка Slack app

В `integrations/slack-manifest.json` добавлены message shortcut
`rele_manage` и bot scope `commands`. В существующей Slack app сохраните
остальные scopes, events, Socket Mode и её действующий Agent/Assistant view.
Внесите эти два дополнения через Slack app settings и переустановите приложение
в нужный workspace с подтверждением изменившихся scopes. Изменение исходников
Rele само не обновляет Slack installation и не запрашивает разрешения.

Message shortcuts находятся в меню сообщения; расположение раздела приложений
зависит от Slack desktop/mobile. Реальный вызов на обеих платформах остаётся
отдельной приёмкой. См. [Slack shortcuts](https://docs.slack.dev/interactivity/implementing-shortcuts/).

## Статус и модель

Статус читает metadata, очередь и Goal через app-server. Он не делает resume,
не создаёт turn и не отправляет модельный запрос. Счётчики запросов относятся
только к исходному Slack-треду. При отключении свежее состояние неизвестно.

Настроенная/сохранённая модель и reasoning effort показываются отдельно от
неподтверждённой фактической пары исполняемого хода. `thread/read` возвращает
конфигурацию загруженного разговора либо последние сохранённые значения, а не
телеметрию конкретного inference.

Модель меняется для **общего Codex-чата со следующих запросов**, включая все
связанные источники. Их количество и область изменения видны перед сохранением.
Исполняемый ход не меняется. Пары берутся из `model/list`; универсального списка
reasoning effort нет. Сохранение использует `thread/settings/update` и чтение
результата. Оно не запускает платный probe. Каталог может быть bundled/cached:
наличие модели не доказывает entitlement провайдера. Неподдержанная пара
отклоняется без подмены. См. [официальный контракт каталога](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server).

## Native Goal

Форма принимает цель, критерий завершения и необязательный положительный лимит
токенов. Их общий native objective ограничен 4000 символами. Пустой бюджет не
вводит неявный лимит; лимит времени здесь не задаётся. Действующая нетерминальная
цель показывается без замены. Запуск требует свободного native разговора и
пустой native очереди.

Используются `thread/goal/set|get`, `origin: user` и native состояния
`active`, `paused`, `blocked`, `usageLimited`, `budgetLimited`, `complete`.
Неподтверждённый/выключенный Goals API явно недоступен; `/goal` в prompt и
скрытого цикла повторных пользовательских запросов нет.

Запуск поддерживается в общем подключении с доступным native UI. Некоторые
первые вопросы и подтверждения нужно завершить в самом Codex; форма сообщает
об этом до отправки. Для доказанных ходов используются также существующие
вопросы и подтверждения Rele.

В managed-режиме «Сервер Rele» новый Goal launch явно недоступен: собственный
child отклоняет неподтверждённые запросы без отдельного native UI. Это ограничение
режима; Status/Model и чтение/приостановка существующей цели остаются доступны.
Приложение не меняет transport автоматически.

Остановка сохраняет native `paused`. На Codex `0.167.0-alpha.4.1` это прекращает
дальнейшее автоматическое продолжение, но само по себе не прерывает текущий ход.
Rele дополнительно запрашивает `turn/interrupt` только для подтверждённого хода
этой цели без чужого ввода. `clear` не используется вместо остановки. При
неподтверждённой принадлежности хода его содержимое и управление остаются в Codex.

Для подтверждённых Goal turns создаётся локальная запись происхождения без
enqueue или prompt. Она использует существующие вопросы/подтверждения Rele.
Публичные завершённые agentMessage items публикуются отдельными сообщениями
в исходном треде после проверки завершённого native хода. Reasoning, команды,
tool events и чужой пользовательский ввод в эту историю не попадают. Итог цели
публикуется отдельно только после native `complete` и завершения её известных
ходов. Завершение одного хода не означает завершения цели.

## Квитанции и восстановление

Форма действует 15 минут. Receipt содержит неизменяемые actor/account/source,
binding/native thread и поколение подключения. Повтор submit одной формы не
создаёт вторую операцию. Перед записью RPC сохраняется `sending`; потеря ACK
оставляет явное `uncertain`. Сохранённая пара модели сверяется чтением native.
Неизвестная Goal mutation не повторяется по совпадающему тексту: native не
возвращает operation key. Её происхождение нельзя восстановить одной строкой
objective.

Goal owner, подтверждённые turn IDs и outbox сохраняются в SQLite metadata Rele.
Повторные события не создают второй результат. Перед отправкой сохраняется
квитанция; неизвестная доставка блокирует последующие этапы до сверки и не
повторяется автоматически. Смена источника не перенаправляет старую доставку.

Перерыв подписки, полностью пропущенный turn-link и неизвестная отправка
оставляют устойчивое UNCERTAIN в Status и квитанциях. Пустая следующая страница
истории не считается разрешением неопределённости. Native complete отображается
отдельно от полноты доставки. Если неизвестны этапы, окончательное закрытие
доставки не подтверждается. Новые события, пришедшие во время native proof или
Slack ACK, объединяются с сохранённым журналом и повторно проверяются перед
закрытием.

Завершённый native owner снимается с новых событий до следующего запуска;
его outbox остаётся привязан к прежнему источнику. Совпадение публичной native
идентичности старой и новой целей изолирует атрибуцию с явным UNCERTAIN, а не
разрешает отправить один результат в два источника. Неопределённая доставка не
подменяет состояние исполнения: подтверждённо завершённый native процесс сам по
себе не блокирует последующий выбор runtime лишь из-за старого outbox.

## Проверенные границы и оставшаяся приёмка

Точная схема и изолированный native fixture проверены на официальных
`0.167.0-alpha.4.1`, `0.167.0-alpha.4.3`, stable `0.167.2` и alpha
`0.170.0-alpha.2` с loopback Responses provider. Fixture не использует auth,
пользовательский профиль, внешний inference или обычный `turn/start`.
Запуск: `RELE_NATIVE_GOALS_CLI=/absolute/path/to/isolated/codex
RELE_NATIVE_GOALS_VERSION=0.170.0-alpha.2 npm test --
tests/native-source-controls.test.ts`; файл результата создаётся только в
временном каталоге fixture.

Проверка установила ограничение native provenance: у Goal нет публичного ID,
а у Turn нет поля принадлежности цели. `thread/goal/updated.turnId` появляется
для активного публичного этапа после agentMessage item и до `turn/completed`.
В первом ходе запрос подтверждения команды может прийти раньше такого события;
пока подтверждение ожидает ответа, привязка ещё не появляется. После явного
native decline появляется accounting event с turn ID. При pause во время
ожидающего inference такой turn-linked event в fixture не появился вовсе.
История пагинируется, но notification replay/cursor контрактом не предоставлен.

Неподтверждённые первые вопросы остаются в native UI общего подключения.
Paused-in-flight и пропущенные turn-link события не приписываются цели по
времени, отсутствию userMessage или тексту: их доставка обозначается UNCERTAIN.
Это поддерживаемая граница сценария, а не отсутствие Goals API.

Зелёные unit/integration и fake-provider проверки не заменяют реальную Slack
desktop/mobile приёмку, проверку установленной версии и штатных пакетов
Windows/Linux. Точные hashes, последовательность первого approval и
capability matrix собраны в [native Goal contract](NATIVE-GOAL-CONTRACT.md).
