# Rele 0.1.1-rc.11 — защита сверки собственных входящих сообщений

Если во время чтения истории изменился набор зарегистрированных собственных
входящих сообщений, результат откладывается до новой сверки. Устаревшее чтение не сохраняет признак смешанного хода и не
подтверждает отправку либо завершение запроса. Защита действует при сверке
исходного запроса и квитанции дополнения.

Типизированный ответ Desktop при таком изменении также ждёт новой проверки.
Окончательный отказ дополнения сохраняется. Проверки чужого ввода, неизвестных
событий и других ошибок чтения остаются прежними; входящие сообщения не
отправляются повторно. Уже сохранённый признак смешанного хода автоматически
не очищается.

Кандидат включает [изменения RC10](0.1.1-rc.10.md): чтение завершённых нулевых
строк native-журналов после подтверждённого заголовка сессии. Native-журналы
не переписываются; отдельная политика сжатия контекста в Rele не добавлена.

Синтетические регрессии проверяют отложенное чтение с новым собственным
дополнением, отказом, чужим вводом и ответом Desktop. Полные Windows/Linux gates и проверка
готовых пакетов на Windows test host/Linux acceptance host привязываются к frozen commit и SHA256 выпуска.
Merge и публикация RC не заменяют живую приёмку или принятие stable.
