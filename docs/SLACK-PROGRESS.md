# Ход работы и результат в одном сообщении Slack

Rele накапливает публичные комментарии Codex в порядке появления. Новый шаг
больше не заменяет предыдущий. Пропущенные события восстанавливаются из
истории того же запроса, включая его продолжения после перегрузки. Повторная
доставка события не дублирует комментарий. Существующий план показывает
текущее состояние пунктов.

Карточка хода работы и окончательный ответ используют один Slack message ID.
Сначала появляется ход работы, затем ниже добавляется итог с форматированием,
таблицами и ссылками. Статус повторов тоже обновляет эту карточку. Вопросы и
подтверждения остаются отдельными интерактивными сообщениями.

Статус и Stop независимы для каждого исходного треда. Если Codex временно не
подтвердил запрос, существующая карточка показывает «Проверяю состояние Codex»
с ранее опубликованными шагами. Rele продолжает сверку без повторной отправки
задачи. Штатный индикатор выполнения и Stop возвращаются после подтверждения
выполняющегося хода; неизвестное состояние не выдаётся за выполнение.

Обычная цепочка видна целиком в раскрываемом блоке. Длинная цепочка разбивается
на части по 6000 символов с кнопками «Назад» и «Далее» в том же сообщении;
ранние шаги сохраняются. По умолчанию показывается последняя часть хода работы.
Длинный итог использует уже подготовленные части ответа, начиная с первой.
Перелистывание меняет общее сообщение для всех участников треда, не запускает
Codex и не считается ответом на вопрос. Выбранная страница сохраняется в Rele.

Показываются только публичные `agentMessage` с фазой `commentary` и план.
Скрытые рассуждения, аргументы инструментов и вывод команд не передаются.
Чужие ходы и ответы после смешанного ввода Desktop/Rele не экспортируются.
Служебные метаданные страницы привязаны к исходным workspace, боту, чату,
треду и ID сообщения; чужая карточка не может получить этот результат.

## Доставка и ограничения

Известный ID сообщения позволяет безопасно повторить замену его содержимого
после потерянного подтверждения `chat.update`. После неопределённой первой
отправки результата автоматического повторного `postMessage` нет.

Исключение из одного сообщения: если Slack не подтвердил первоначальную
отправку **только прогресса**, Rele не знает её ID. Тогда итог отправляется
отдельно, чтобы не потерять ответ. Неподтверждённый итог так не дублируется.
Старые уже завершённые запросы и отправленные сообщения массово не переписываются.

Используются штатные [task_card](https://docs.slack.dev/reference/block-kit/blocks/task-card-block/)
и [chat.update](https://docs.slack.dev/reference/methods/chat.update/).
Ответ разбит с учётом общего лимита [Markdown-блоков](https://docs.slack.dev/reference/block-kit/blocks/markdown-block/).

Локальные проверки подтверждают накопление, восстановление истории, пагинацию,
доставку в один message ID, потерянные ACK и защиту чужих/смешанных источников.
Рендеринг и клики в настоящем Slack на этой версии ещё не проверены.
