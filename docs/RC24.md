# Rele 0.1.0-rc.24

На уточнения Codex теперь можно отвечать средствами Slack. Один вопрос с короткими вариантами показывает кнопки выбора; собственный ответ вводится в модальном окне Slack. Для нескольких вопросов кнопка ответа открывает общую форму со всеми вопросами.

Ответ передаётся в исходный native RPC `item/tool/requestUserInput` и продолжает ожидающий ход. Новый запрос, ход или `turn/steer` для этого не создаётся. Управление доступно только в исходном обсуждении собственного запроса Rele, с прежней проверкой отправителя. Уточнения чужих задач и самостоятельных ходов Desktop не становятся управляемыми из Slack.

Для поддерживаемых ожидающих вопросов Rele повторно сверяет каноническую историю только на чтение, в пределах той же эпохи соединения и пока исходный RPC остаётся открытым. Ответ при такой проверке повторно не отправляется. Неподдерживаемые асинхронные RPC и вопросы задач Desktop остаются вне этого управления.

После отправки ответа из Slack карточка показывает известного отправителя и его несекретные ответы. Если Codex сообщает только о закрытии запроса, карточка говорит об этом без указания участника или причины: такое событие не доказывает, кто ответил или почему вопрос закрылся. Повторное действие с уже закрытым вопросом не создаёт новую задачу.

Секретные ответы вводятся только в локальной панели Rele. Они не передаются в кнопки, формы или карточки Slack.

RC не меняет Codex Desktop, backend, способ их подключения, зависимости или схему базы Rele. Исходные профиль, ID и история разговоров сохраняются. [Поведение предыдущего кандидата](RC23.md) остаётся в силе.

Проверки точного commit и пакетов приводятся в GitHub release. Реальный рендеринг кнопок и форм Slack, доставка и управление из мессенджеров и с телефона ещё не приняты. Перезагрузка ОС и длительная эксплуатация остаются отдельными проверками. Ранее наблюдавшиеся аварии native backend не объявляются исправленными; ограничения экспериментального native API, локального WebSocket без токена и неподписанного Windows RC сохраняются.
