# Эксплуатация Rele

## Каталог программы и данные

Распакуйте выпуск в постоянный каталог. Данные находятся отдельно: Windows — LOCALAPPDATA/Rele; Linux — XDG_STATE_HOME/rele или ~/.local/state/rele. RELE_DATA_DIR переопределяет путь.

Все процессы используемой связки работают на одной машине под нужным владельцем Codex. Не запускайте Windows Rele как SYSTEM: DPAPI и профиль Desktop принадлежат пользовательской сессии.

Порт по умолчанию 3210. RELE_PORT меняет его; приложение всё равно слушает только 127.0.0.1. Для удалённой панели Ubuntu используйте SSH-туннель. Второй процесс с тем же каталогом данных не запускается.

## Управление

Launcher принимает команды:

| Команда | Результат |
| --- | --- |
| без аргументов / serve | Запуск HTTP, адаптеров и очереди |
| token | Показ ключа панели в локальном терминале |
| diagnostics | Версия, платформа, адрес процесса и включённые подключения без токенов |
| backup [новый каталог] | Online snapshot SQLite и копия конфигурации |
| version / --version | Версия пакета |
| help / --help | Справка |

Остановите интерактивный процесс Ctrl+C. Rele прекращает приём событий, закрывает соединения и сохраняет состояния, пригодные для последующей сверки. Он не завершает сам общий Codex daemon.

В истории остаются запросы, распознанный текст, подтверждения и исходящие ответы. Автоматическая очистка журнала в первом выпуске не предусмотрена. Исходные аудиофайлы временные и удаляются после обработки.

## Автозапуск Windows

Запустите install-autostart.cmd из каталога выпуска. Установщик создаёт запись Startup для текущего пользователя; запуск выполняется при его следующем входе. Для удаления:

```powershell
.\install-autostart.cmd --remove
```

Данные сохраняются. Текущую работающую копию остановите отдельно. После перемещения программы переустановите запись автозапуска.

## Автозапуск Ubuntu Server

В пользовательской сессии владельца Codex:

```bash
./install-user-service.sh
systemctl --user status rele
journalctl --user -u rele -n 50
```

Установщик сохраняет нужный PATH и заданные CODEX_HOME / RELE_DATA_DIR. Секреты мессенджеров остаются в закрытой конфигурации Rele.

Для работы пользовательского service после logout администратор сервера должен включить lingering для этого пользователя. Этот системный шаг не выполняется установщиком автоматически.

```bash
systemctl --user stop rele
systemctl --user start rele
./install-user-service.sh --remove
```

Rele не управляет жизненным циклом общего Codex runtime. Настройте его отдельно и проверьте подключение CLI к тому же серверу.

## Резервная копия

```bash
./start-rele.sh backup /absolute/path/rele-backup-2026-10-18
```

Windows:

```powershell
.\start-rele.cmd backup C:\Backups\Rele-2026-10-18
```

Каталог назначения должен быть новым. Копирование живой базы выполняется SQLite backup API и учитывает WAL; простое копирование одного rele.sqlite во время работы не является эквивалентом.

Backup содержит базу, config.json и метаданные выпуска. Он содержит историю и секреты подключения, поэтому храните его с доступом только владельца. DPAPI-секреты Windows доступны исходному пользователю на исходной машине; при переносе потребуется повторная настройка токенов.

## Восстановление

1. Остановите Rele.
2. Сохраните текущий каталог данных отдельно, если он нужен для разбора.
3. В новый пустой каталог данных скопируйте rele.sqlite и config.json из backup.
4. Укажите этот каталог через RELE_DATA_DIR или замените прежний каталог целиком. Не смешивайте восстановленную базу со старыми файлами -wal / -shm.
5. Запустите ту же либо совместимую более новую версию Rele под нужным пользователем.
6. Проверьте подключения, очередь и неопределённые доставки перед продолжением.

Восстановление Rele не восстанавливает Codex history и рабочие файлы проекта. Их резервное копирование выполняется отдельно. Сверка может потребовать тот же Codex thread/profile.

## Обновление

Сначала создайте backup, остановите текущую версию, распакуйте новый выпуск в новый каталог и запустите его с тем же RELE_DATA_DIR. Данные не должны находиться внутри заменяемого каталога программы. Переустановите автозапуск для нового пути.

Схема SQLite мигрирует транзакционно. Более старая программа отказывается открывать более новую схему. Для отката после миграции верните и старую программу, и совместимый backup, а не только старые файлы программы.

## Неопределённые состояния

«Сверить» перечитывает очередь и историю Codex; не запускает запрос заново. «Продолжить» пытается запустить уже существующий server queue item и не меняет занятый чужой ход. «Отменить» удаляет известный queue item либо прерывает известный turn.

Если исходящий ответ отмечен uncertain, проверьте его наличие в исходном мессенджере. Автоматический повтор недоступен: потерянное подтверждение не доказывает отсутствие сообщения. При недоказанном состоянии Rele предпочитает остановить соответствующую последовательность доставки.

Если запрос отсутствует и в очереди, и в доступной истории, Rele не делает предположение о повторном запуске. Исходные диагностики нужно сверить с Codex; удаление истории Codex до завершения такой проверки мешает восстановлению.
