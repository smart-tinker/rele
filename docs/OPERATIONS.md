# Эксплуатация Rele

## Установленное приложение

Основной путь — [Windows Setup или Debian-пакет](INSTALLATION.md). Windows: `%LOCALAPPDATA%\Programs\Rele`, Ubuntu Server: `/opt/rele`. Данные находятся отдельно: Windows — `%LOCALAPPDATA%\Rele`; Linux — `~/.local/state/rele` по умолчанию. Настройки установленной службы сохраняют выбранные каталоги между обновлениями.

Windows: ярлыки «Открыть Rele», «Перезапустить Rele» и «Остановить Rele» управляют пользовательской задачей. Служба Ubuntu: `rele service status`, `sudo rele service restart` / `stop` / `start`. После выхода из SSH системная служба Ubuntu продолжает работать под владельцем Codex. Windows-задача живёт в пользовательской сессии и запускается при входе.

Журнал Windows: `%LOCALAPPDATA%\Rele\logs\service.log`. Ubuntu: `sudo journalctl -u rele -n 50`. Локальный API и панель слушают только `127.0.0.1`, порт по умолчанию 3210. Для Ubuntu с другого компьютера используется SSH-туннель.

Все процессы связки работают на одной машине под владельцем Codex. Windows Rele не запускается как SYSTEM: DPAPI и профиль Desktop принадлежат пользовательской сессии. В рекомендуемом shared режиме Rele подключается к штатному daemon и восстанавливает его запуск; остановка Rele завершает только свой connection/proxy. Дополнительный managed режим владеет отдельным stdio child и останавливает его вместе с Rele. Ручные proxy / WebSocket подключения сохраняются.

## Ограниченная диагностика

Изменение ниже входит в rc.12. В rc.11 и старше команда `diagnostics` по-прежнему загружает конфигурацию; не используйте её как проверку без доступа к секретам.

Исправленная команда выполняет только чтение `instance.json` и, для допустимого loopback-адреса с живым PID, GET `/api/health`. Она не загружает `config.json`, не расшифровывает DPAPI, не читает базы Rele/Codex и не создаёт каталог данных. Запрос не содержит ключа панели, не следует redirects и ограничен таймаутом. В JSON выводятся версия запускаемого Rele/Node/ОС и только разрешённые поля проверки экземпляра: категория состояния, PID, признак живого процесса, HTTP-код и совпадение версий. Пути, адреса, произвольные поля marker и сырые ошибки не выводятся.

Ubuntu под владельцем Rele:

```bash
rele diagnostics
```

Windows, для установленной исправленной версии:

```powershell
& "$env:LOCALAPPDATA\Programs\Rele\runtime\node.exe" "$env:LOCALAPPDATA\Programs\Rele\dist\server\main.js" diagnostics
```

При нестандартном каталоге данных используйте уже настроенный `RELE_DATA_DIR`. Это запуск существующего проверяемого файла приложения с фиксированным аргументом; код не передаётся в командной строке или stdin. Для удалённого вызова применим тот же короткий вызов установленной команды через штатный SSH. Универсальный transport произвольных PS/JS scripts не используется.

`instance.marker` отличает absent/valid/invalid/unreadable. `health` отличает not-checked/responding/mismatch/unavailable. Отсутствующий или некорректный marker не вызывает сетевой запрос. `responding` означает только ответ публичного health API с совпавшей версией; это не аутентифицированная проверка владельца, готовности Codex, приёма/доставки Slack или качества контекста. `desktopVerified` остаётся false. Команды `status`, `open`, `stop` имеют отдельный контракт с загрузкой конфигурации и не заменяют такую диагностику.

Если этих метаданных недостаточно, заранее определите отдельный узкий доступ и проверяемый локальный код с ограниченным результатом. Не подменяйте это чтением `/api/state`, конфигурации или истории через ad-hoc скрипт. Не использовать `-EncodedCommand`, Base64/ScriptBlock/Invoke-Expression или скрытый stdin как способ доставки диагностики. Не отключать Defender/AMSI/ETW и не добавлять исключения ради выполнения; при блокировке сохранить статус и остановить проверку. Отсутствие будущих ложных срабатываний не гарантируется. Проверка на Windows с включённой защитой ещё необходима.

## Переносимый запуск

ZIP / TAR можно распаковать в постоянный каталог и использовать `start-rele.cmd` / `start-rele.sh`. `RELE_DATA_DIR` задаёт каталог данных, `RELE_PORT` — порт; прежний `XDG_STATE_HOME` поддерживается при прямом запуске Linux. Терминал остаётся открытым до завершения через `Ctrl+C`.

Если Windows пишет «Системе не удаётся найти указанный путь», но оба файла существуют, доступен прямой запуск:

```powershell
Test-Path -LiteralPath '.\runtime\node.exe' -PathType Leaf
Test-Path -LiteralPath '.\dist\server\main.js' -PathType Leaf
& '.\runtime\node.exe' '.\dist\server\main.js'
```

Во втором PowerShell из той же папки: `& '.\runtime\node.exe' '.\dist\server\main.js' open`. При необходимости получите ключ командой `token` вместо `open`. Штатный Setup использует нативный launcher и не требует исправления CMD для запуска установленного приложения. Причина конкретного сбоя старого launcher отслеживается в [issue #6](https://github.com/smart-tinker/rele/issues/6).

Legacy portable автозапуск: `install-autostart.cmd` на Windows, `install-user-service.sh` на Linux. Удаление такой записи — соответствующий скрипт с `--remove`; программа и данные при этом остаются. Пользовательский systemd service требует отдельно настроенного lingering для работы после logout. Новый `.deb` использует системную службу под владельцем Codex и не требует lingering.

## Резервная копия

```bash
./start-rele.sh backup /absolute/path/rele-backup-2026-10-18
```

Windows, для установленного приложения из его каталога:

```powershell
& ".\runtime\node.exe" ".\dist\server\main.js" backup C:\Backups\Rele-2026-10-19
```

При нестандартном каталоге данных задайте `RELE_DATA_DIR` как в `rele-install.json`. Ubuntu с установленным пакетом: `rele backup /absolute/path/rele-backup-2026-10-19`.

Каталог назначения должен быть новым. Копирование живой базы выполняется SQLite backup API и учитывает WAL; простое копирование одного rele.sqlite во время работы не является эквивалентом.

Backup содержит базу, config.json и метаданные выпуска. Он содержит историю и секреты подключения, поэтому храните его с доступом только владельца. DPAPI-секреты Windows доступны исходному пользователю на исходной машине; при переносе потребуется повторная настройка токенов.

## Восстановление

1. Остановите Rele.
2. Сохраните текущий каталог данных отдельно, если он нужен для разбора.
3. В новый пустой каталог данных скопируйте rele.sqlite и config.json из backup.
4. Укажите этот каталог через RELE_DATA_DIR или замените прежний каталог целиком. Не смешивайте восстановленную базу со старыми файлами -wal / -shm.
5. Запустите ту же либо совместимую более новую версию Rele под нужным пользователем.
6. Проверьте подключения, очередь и неопределённые доставки перед продолжением.

Восстановление Rele не восстанавливает Codex history и рабочие файлы проекта. Их резервное копирование выполняется отдельно. Сверка может потребовать тот же Codex thread/profile.

## Обновление

Штатная установка: запустите новый Windows Setup или `sudo apt install ./rele-<версия>-linux-x64.deb`. Установщик останавливает свой Rele, создаёт backup прежним runtime до замены и запускает новую версию. Пользовательские данные хранятся отдельно. Удаление программы их сохраняет. [Полный сценарий](INSTALLATION.md).

Для смены версии общего Codex панель отдельно показывает работающий сервер, выбранную версию и новейшую найденную установку. Автоматическая политика выбирает только среди уже установленных поддерживаемых версий; Windows Store может ещё не предложить новый пакет. Сначала подготовьте обновление, затем завершите задачи и закройте остальные клиенты Codex. После подтверждения примените обновление. Отказ «занят» или «открыт другой клиент» сохраняет очередь и допускает повтор после устранения причины; новая попытка требует нового подтверждения закрытых клиентов. На Linux управляемая замена разрешена для штатного native daemon, а не произвольной внешней службы.

Rele не обновляет MSIX Desktop. Если штатная установка Windows возвращает `0x80073D02`, пакет может удерживать sandbox service даже после закрытия Desktop. Обновляйте пакет штатными средствами Windows; Rele не останавливает эту SYSTEM-службу автоматически.

Windows native `codex-postflight` запускается после подтверждённого подключения и очищает только проверенные собственные остатки. Текущие, используемые и recovery paths сохраняются вместе с историей, auth и профилем. Неизвестные кандидаты остаются; технические сведения показывают освобождённые байты, число удалённых и сохранённых объектов. Inno удаляет свой `{tmp}`, dpkg заменяет старый payload Rele. Эти действия не означают очистку всех кешей или других установок Codex.

Portable: сначала создайте backup, остановите текущую версию, распакуйте новый архив в новый каталог и запустите его с тем же `RELE_DATA_DIR`. Данные должны находиться вне заменяемого каталога. Переустановите legacy автозапуск для нового пути либо перейдите на штатный установщик.

Схема SQLite мигрирует транзакционно. Более старая программа отказывается открывать более новую схему. Для отката после миграции нужны и прежняя программа, и совместимый backup. Переход rc.1 → rc.2 изменил схему v2 → v3; rc.3, rc.4 и rc.5 сохраняют v3. rc.6 мигрирует v3 → v4 для durable журнала Slack; откат к rc.5 и старше требует backup до миграции. rc.9 мигрирует v4 → v5 для нескольких origin и durable автосоздания; перед обновлением сохраните штатный backup. Откат к rc.8 и старше требует совместимой копии до миграции; не восстанавливайте её поверх новых запросов/доставок без отдельной сверки. Возврат к rc.1 требует копии, созданной до первой миграции.

## Связи и режимы доступа rc.12

Страница «Связи» содержит Telegram/Slack и все обнаруженные треды. В колонке Codex выберите назначение или автосоздание с рабочей папкой. Права задайте на отдельной странице «Доступ»; по умолчанию новый источник выключен. Существующие ограничения отправителей сохраняются; явное сохранение нового группового режима разрешает всех участников. Личному чату нужен выбранный человек, не бот.

Обычное переназначение невозможно при незавершённых запросах и автосоздании. При uncertain/failed выберите проверенный созданный разговор и подтвердите «Продолжить сохранённые запросы»; это отдельное восстановление принятых событий, а не перенос только будущих сообщений. Известный native ID и рабочая папка должны совпадать. Потерянный create ACK автоматически не повторяется.

Выключенный источник не передаёт новый контекст и не запускает новые задачи. Уже работающие задачи и их origin-контроль сохраняются. Принятый Slack-запрос может ждать включения для проверки полной истории; его можно отменить. Другие источники общего Codex продолжают работу. После повторного включения история треда может быть дозагружена полностью.

SQLite v6 не переписывает таблицы/историю, но блокирует старые бинарники, игнорирующие новую политику. До обновления сохраните штатный backup; для отката к rc.11 и старше требуется pre-v6 backup. Не восстанавливайте его поверх новых принятых запросов без отдельной сверки.

## Неопределённые состояния

«Сверить» перечитывает очередь и историю Codex; не запускает запрос заново. «Продолжить» пытается запустить уже существующий server queue item и не меняет занятый чужой ход. «Отменить» удаляет известный queue item либо прерывает известный turn.

Если исходящий ответ отмечен uncertain, проверьте его наличие в исходном мессенджере. Автоматический повтор недоступен: потерянное подтверждение не доказывает отсутствие сообщения. При недоказанном состоянии Rele предпочитает остановить соответствующую последовательность доставки.

Если запрос отсутствует и в очереди, и в доступной истории, Rele не делает предположение о повторном запуске. Исходные диагностики нужно сверить с Codex; удаление истории Codex до завершения такой проверки мешает восстановлению.

## Общий сервер Codex

В рекомендуемом «Общий Codex» Windows Desktop и Rele подключены прямо к одному native app-server по loopback WebSocket; Ubuntu Rele и обычный CLI используют native daemon/UDS. После восстановления Rele сверяет уже принятые UUID по очереди и истории. Потерянный ACK не разрешает повторять задачу. После Stop автоматически продолжается только единственная точная собственная запись native-очереди; смешанная или чужая очередь сохраняется для явной проверки.

На Ubuntu `systemctl status rele-codex.timer rele-codex.service` показывает независимый starter вне cgroup Rele. На Windows общий сервер принадлежит отдельной задаче `Rele-<SID>-Codex`, а не gateway. Остановка Rele не останавливает native server. Windows endpoint постоянный и только127.0.0.1 без токена; он доступен другим локальным процессам/пользователям. Занятый неподтверждённым процессом порт блокирует запуск: не завершайте этот процесс и не меняйте порт вслепую.

Старый недоступный локальный WebSocket переводится установщиком в «Общий Codex» после проверки исходного профиля и очереди. Работающий, удалённый, защищённый отдельным ключом target и другой профиль сохраняются для явной проверки. После успешной интеграции дождитесь завершения задач, один раз полностью выйдите из private Desktop и откройте обычным способом. Повторять Quit на каждый запрос не требуется. Не копируйте историю или профиль и не завершайте произвольный codex.exe по имени/PID. [Установка](INSTALLATION.md#общий-codex-и-переход-с-предыдущего-rc).

## Занятый тред и профиль Codex

«В очереди» с сообщением о занятом треде означает, что другой процесс Codex удерживает право записи. Запрос уже записан в Rele и ещё не отправлен в очередь Codex; можно подождать или отменить его. Rele повторяет открытие того же ID через пять секунд. Конец ответа в Desktop не всегда освобождает тред: при необходимости закройте Desktop и дождитесь исчезновения его процесса. Rele сам не завершает сторонний Desktop.

После завершения и сверки своего хода Rele освобождает тред. Пока он освобождается, следующий запрос не запускается. В managed-режиме закрытие Rele останавливает его дочерний app-server; уже начавшиеся запросы при следующем запуске сверяются по исходным UUID, а не отправляются заново.

Если каталог пуст или видны другие чаты, проверьте фактический профиль в разделе «Codex». При необходимости укажите точный путь к существующему профилю Desktop/CLI. Не создавайте private CODEX_HOME с подставленными файлами истории: процессы должны использовать один настоящий профиль и одинаковые настройки хранилища Codex. Backup Rele этот профиль не включает.
