# Rele 0.1.0-rc.7

- Ожидание свободного треда, очередь Codex и неопределённая готовность показываются отдельно. Slack Working остаётся только при распознавании аудио и фактическом выполнении.
- Пассивный Slack-контекст поддержан и для общего локального proxy/WebSocket-сервера. Rele проверяет платформу, тот же профиль и исходный тред; запись помечается переданной только после чтения точного маркера из native JSONL. Потерянный ACK сверяется перед повтором; отмена активного хода не создаёт скрытого пробела.
- Собственный запрос можно отменить из его исходного обсуждения: обычное сообщение `rele:cancel` в Slack, `/rele_cancel` в Telegram. Команда останавливает текущий собственный запрос, либо самый ранний ещё ожидающий. Смешанный с другим клиентом ход автоматически не прерывается. Повтор входящего события не запускает новую задачу и не повторяет отмену.
- На несколько обычных вопросов Codex можно ответить из мессенджера: по одной строке `1. ответ`, `2. ответ` и далее. Секретные поля сохраняют прежний ввод в локальной панели.

Открытый Desktop и Rele должны подключаться к **одному процессу app-server**. Два отдельных managed/stdio-процесса с одним профилем по-прежнему конкурируют за запись. Само обновление Rele не переключает Desktop и не меняет его запуск. Разовый переход на общий сервер требует отдельной настройки Desktop; закрывать Desktop на время каждой задачи не требуется после такого перехода. Общая native очередь без общего owner не обеспечивает управление подтверждениями и отменой из мессенджера и не используется как обход.

Rele сохраняет исходные ID, историю и профиль; не создаёт fork и не переписывает native сообщения. Источники в исходном ответе сохраняются. Отображение citation directives и кружка в обычном списке Slack Threads остаётся поведением клиентских приложений; Rele управляет штатным статусом внутри обсуждения.

SQLite остаётся v4. Изменение не требует миграции или копирования профиля Codex. Поддержаны Codex 0.163.0 и 0.163.0-alpha.10.2. Общий сервер должен быть локальным, под тем же пользователем и с тем же профилем. Сжатый `.zst` rollout или неподтверждённая запись оставляют контекст в журнале с видимой причиной.

Выпуск остаётся неподписанным RC. Автоматические проверки не заменяют приёмку конкретного Windows Desktop и настоящих Slack/Telegram; она остаётся открытой в [ACCEPTANCE.md](ACCEPTANCE.md).
