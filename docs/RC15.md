# Rele 0.1.0-rc.15

## Обычный запуск Desktop

Установщик по умолчанию подключает обычные запуски Codex Desktop к общему native серверу Rele. Исправлен сброс этой интеграции при обновлении: прежний выбор теперь сохраняется, включая явное отключение. Раньше задача Inno Setup имела `checkedonce`, из-за чего повторная установка могла снять флажок и восстановить прежнее окружение Desktop.

После установки один раз полностью выйдите из уже работающего Desktop и откройте его обычным способом. Специальный ярлык и ручное задание переменных для стандартной установки не требуются. Дополнительный ярлык общего Desktop остаётся для явного запуска из правильного окружения. Если Desktop запускается из давно открытого терминала или другого приложения со старым окружением, перезапустите это родительское приложение.

Файлы Desktop не изменяются. Интеграция использует пользовательские CODEX_CLI_PATH и CODEX_APP_SERVER_FORCE_CLI и прежний immutable адаптер. Чужие конфликтующие настройки сохраняются с предупреждением. Удаление Rele восстанавливает только принадлежащие ему значения. Установщик не завершает Desktop или его активные задачи.

## Обычный Codex CLI на Ubuntu Server

Под владельцем Rele, с тем же CODEX_HOME, используйте обычные команды:

```sh
codex
codex resume ID
```

В трёх поддерживаемых версиях native `daemon_auto_start` включён по умолчанию. Стандартный интерактивный CLI подключается к тому же daemon или запускает его штатным способом. Rele не заменяет установленную команду Codex, не правит shell/profile и не создаёт отдельную историю. `.deb` сохраняет независимый starter/timer общего сервера после выхода из SSH и при загрузке системы.

Явные `--no-daemon`, `--oss`, `--profile`, отдельные startup overrides и отключённый `daemon_auto_start` меняют штатный выбор runtime. При предупреждении CLI о работе без общего сервера такой запуск нельзя считать подключением к Rele. Для строгого подключения остаётся `rele codex` с явным `--remote`. `codex exec` общий remote в проверяемых версиях не поддерживает.

## Сохранность и проверка

Профиль, история, thread/request IDs, SQLite v6 и управление запросами из исходного канала сохраняются. Новых runtime-зависимостей, миграций БД, vendor/PATH wrappers нет. Существующие явные managed/proxy/WebSocket подключения не меняются автоматически.

Установочная проверка использует обычные defaults без принудительного `/TASKS=desktop` и сверяет интеграцию после установки, обновления и явного отключения. Linux native проверка открывает исходный уже загруженный тред настоящим интерактивным CLI через PTY без `--remote`, подтверждая тот же daemon PID, контекст и отсутствие внешней доставки прямого CLI-ответа. Результаты итогового CI фиксируются в PR и выпуске.

Проверки окружения установщика не заменяют реальный Desktop GUI и запуск через Explorer/AppsFolder. Живые GUI, мессенджеры с телефона и reboot остаются пользовательской приёмкой. Stable не выпускается этой итерацией.
