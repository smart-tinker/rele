# Rele 0.1.0-rc.6

- Штатный индикатор работы Slack: очередь, запуск, распознавание, выполнение и ожидание подтверждения. Обновляется во время работы, очищается после завершения; ошибка индикатора не отменяет запрос.
- Native Slack Markdown blocks для rich-ответов с таблицами, кодом, заголовками и списками. Длинные таблицы сохраняют заголовки; слишком широкие/длинные строки получают читаемый code fallback. Codex file citations становятся путями, исходящие упоминания не запускают каскад ботов.
- Полный доступный контекст связанного Slack-треда: все авторы, другие агенты, собственные ответы, blocks, attachments и metadata файлов. Новая задача ждёт предшествующий контекст. История, правки и удаления служат контекстом и не запускают задачи задним числом.
- Другому выбранному боту разрешён запуск только новым прямым упоминанием подключённого Slack-агента. Неотмеченный автор не запускает задачу; цитаты/код и собственные ответы Rele не образуют цикл.
- В настройках связки — журнал исходных сообщений, ревизий и передачи в Codex, с пагинацией и видимыми ошибками. Backfill всех страниц, восстановление после перезапуска и полный rescan при reconnect не имеют ограничения на последние N сообщений.

## Обновление и границы

Нужен режим «Сервер Rele» с Codex 0.163.0 либо 0.163.0-alpha.10.2. Внешний общий proxy/WebSocket не позволяет безопасно гарантировать idle-проекцию: контекст сохраняется в журнале и ждёт managed-подключения. Telegram-only связки продолжают работать как прежде.

Пассивный `thread/inject_items` сохраняет контекст модели без запуска ответа, но Desktop не показывает его отдельными сообщениями. При потерянном ACK пассивная цитата может повториться с тем же маркером; запросы с неизвестным ACK по-прежнему не отправляются заново автоматически. История ограничена доступными Slack API данными и обычным сжатием Codex. Исчезнувшие до наблюдения сообщения восстановить невозможно. Произвольные файлы представлены metadata, их содержимое автоматически не извлекается.

SQLite мигрирует v3 → v4. Установщики сохраняют данные и создают backup; откат к rc.5 требует backup v3. Перед ручным обновлением portable используйте `rele backup` и остановите старый процесс. Изучены исходники OpenClaw и Hermes; используется стандартный Slack API без новых runtime-зависимостей.

Выпуск остаётся неподписанным RC. Native CI проверяет обе ОС, обе закреплённые версии Codex, реальные установщики и синтетические мессенджеры; это не подтверждает ещё реальный spinner/rendering в пользовательском Slack и Windows Desktop. Приёмка — [ACCEPTANCE.md](ACCEPTANCE.md).
