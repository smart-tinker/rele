# Rele 0.1.0-rc.18

Исправлен переход к общему Codex на Windows, когда сохранённый служебный каталог имеет унаследованные права. В rc.17 наличие оставшегося AF_UNIX сокета уже обрабатывалось, но штатный daemon мог отказать с `socket directory is not private to the current user`. В результате Rele оставался без соединения даже после выбора «Общий Codex».

Перед запуском daemon Rele теперь выполняет ограниченную подготовку `CODEX_HOME\app-server-control`. Проверяются текущий владелец, обычные каталоги без reparse points и только известные служебные записи. Native operation lock исключает одновременную lifecycle-операцию штатного daemon; под блокировкой выполняется свежий read-only probe. Перенос допускается только при подтверждённом отказе соединения с ожидаемым сокетом. Работающий общий сервер сохраняется; отдельный private Desktop и неизвестный владелец блокируют подготовку.

Старый каталог переименовывается в `app-server-control.rele-backup-<nonce>` с сохранением его содержимого и ACL. По исходному пути публикуется новый каталог того же пользователя с private ACL. Права старого объекта не переписываются: ранее открытые handles остаются связаны с резервным объектом. Публикация использует удерживаемые handles и не заменяет существующий путь. При ошибке публикации предпринимается обратный перенос; неподтверждённый откат также возвращает ошибку. Неизвестное содержимое, reparse point, занятая блокировка, timeout или неподтверждённый результат останавливают операцию. Авторизация, история, `config.toml` и исходные ID разговоров сохраняются.

В разделе «Codex» появился отдельный статус настройки обычного запуска Desktop и явные кнопки включения/отключения интеграции. Если установщик ранее пропустил её из-за старого WebSocket target или неуспешной проверки, выберите shared с исходным профилем, сохраните настройки и нажмите «Подключить обычный Codex Desktop». Сохранение shared само по себе hook не включает. Повторная проверка проходит через штатный установленный launcher без переустановки, остановки Rele или закрытия работающих окон и задач. После успешного включения дождитесь завершения задач, полностью выйдите из Desktop и откройте его обычным способом.

Панель показывает записанное состояние установки, отдельно от соединения Rele с сервером и фактического подключения уже открытого Desktop. Сырые сообщения установщика и дочерних процессов в API не возвращаются. Ранее выбранный отказ от интеграции и конфликтующие чужие настройки сохраняются. Смена target и действия интеграции выполняются последовательно; перед сменой сервера или профиля включённую интеграцию нужно явно отключить. Последняя ошибка подключения остаётся видимой во время повторной попытки и очищается после успешного соединения.

Отказ rc.17 с унаследованными ACL и настоящим AF_UNIX сокетом воспроизведён в изолированном профиле на Windows windows-test-host; восстановление через production-путь подтверждено на подготовленном исправлении. Три новых сценария панели прошли с синтетическими API-ответами, включая retry после отказа и недоступность действий вне установленного Windows Rele. Сведения о приёмке итогового commit и финальных Windows/Linux пакетов rc.18 — в описании GitHub release. Эти результаты не подтверждают новую live-доставку Slack/Telegram, reboot или длительную работу; условия стабильного выпуска остаются в [ACCEPTANCE.md](ACCEPTANCE.md).
