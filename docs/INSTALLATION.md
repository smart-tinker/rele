# Установка, обновление и удаление

Имена файлов ниже показаны как шаблон. Опубликованные версии и проверки конкретных пакетов доступны в [GitHub Releases](https://github.com/smart-tinker/rele/releases).

| Система | Файл | Файлы программы | Фоновый запуск |
| --- | --- | --- | --- |
| Windows x64 | `rele-<версия>-windows-x64-setup.exe` | `%LOCALAPPDATA%\Programs\Rele` | Задача текущего пользователя при входе Windows |
| Ubuntu Server x64 | `rele-<версия>-linux-x64.deb` | `/opt/rele`, команда `/usr/bin/rele` | Служба systemd `rele.service` под владельцем Codex |

Пакеты включают Node.js 24.19.0 и зависимости Rele. Пользователю не нужен npm. Codex устанавливается отдельно; Windows Rele использует доступный установленный backend Desktop или CLI. Для локальных голосовых отдельно нужны Python и модель. WSL не используется.

Скачивайте пакет и соответствующий `.sha256` из одного выпуска [GitHub Releases](https://github.com/smart-tinker/rele/releases). Windows: `Get-FileHash -Algorithm SHA256 <пакет>`. Ubuntu: `sha256sum -c <пакет>.sha256`. RC пока не подписан сертификатом Windows и не распространяется через APT-репозиторий. Обновление выполняется запуском нового установщика или установкой нового `.deb`; скрытого фонового скачивания обновлений нет.

## Windows

Запустите Setup под своей обычной учётной записью Codex Desktop. Администраторская установка и отдельная учётная запись SYSTEM не требуются. Мастер сам размещает файлы, создаёт запись удаления, ярлыки и фоновую задачу. На последнем шаге открывается панель в браузере.

Оставьте выбранной задачу интеграции Desktop. Установщик сам выбирает общий Codex и подключает обычный запуск Desktop. Старый недоступный локальный WebSocket без отдельного ключа заменяется автоматически после проверки исходного профиля и очереди; исходный зашифрованный config сохраняется в backup. Удалённый сервер, работающий старый endpoint, другой профиль и незавершённые операции требуют проверки и сохраняются без автоматической замены. Отказ от интеграции из панели или прошлого установщика сохраняется. Временный отказ запуска общего Codex не отменяет выбранную интеграцию: после подтверждённого восстановления Rele повторяет её один раз за запуск.

Если Desktop уже открыт, дождитесь завершения задач, выполните один полный Quit через трей и откройте его обычным способом. Специальный ярлык и ручной выбор режима в панели не нужны. Приложение Desktop и его файлы не изменяются. [Правила автоматического перехода](RC19.md).

В «Пуск» доступны:

- **Открыть Rele** — запускает фоновую задачу, дожидается готовности и открывает панель.
- **Перезапустить Rele** — штатно останавливает текущий Rele, запускает задачу заново и открывает панель.
- **Остановить Rele** — завершает текущий процесс. При следующем входе в Windows автозапуск остаётся включён.

Задача `Rele-<SID текущего пользователя>` использует `InteractiveToken` и `LeastPrivilege`. Она работает в сессии пользователя, сохраняет доступ к профилю Codex и DPAPI, повторяет запуск при сбое. После выхода пользователя процесс завершается; следующий вход запускает его снова. Для постоянного сервера без пользовательской сессии предназначен вариант Ubuntu Server.

Нативный `Rele.exe` запускает комплектный Node напрямую. CMD / PowerShell launcher не участвует в обычном открытии установленного приложения. Журнал: `%LOCALAPPDATA%\Rele\logs\service.log`; ротация ограничивает размер файла. Данные и резервные копии находятся отдельно от программы.

### Переход с ZIP

Если переносимый Rele ещё работает в PowerShell, завершите его через `Ctrl+C` перед установкой. Установщик не останавливает процессы из другой папки автоматически. Стандартный каталог `%LOCALAPPDATA%\Rele` подхватывается вместе с настройками, токенами и связками. Повторный ввод ключей при той же учётной записи и машине не требуется.

Прежний Startup launcher, созданный `install-autostart.cmd`, переносится автоматически: установщик проверяет его точный формат, прежний пакет и каталог данных. После успешного запуска новой задачи исходный скрипт сохраняется в `backups/legacy-startup-...` и убирается из автозапуска. Если файл был изменён вручную или относится к другому профилю, установка остановится с объяснением; такой скрипт не удаляется автоматически.

### Обновление

Запустите Setup новой версии под тем же пользователем. Установщик использует прежнюю папку программы и тот же каталог данных. До замены он останавливает собственную фоновую задачу, дожидается завершения и создаёт резервную копию с помощью прежнего runtime в `Rele\backups`. Ошибка остановки или backup прерывает замену файлов. После установки задача запускается заново.

Резервная копия — способ отката данных, а не обещание автоматического отката ОС при аварийном выключении. При смене схемы SQLite для возврата старой версии нужны и старый пакет, и соответствующий backup. С rc.12 используется SQLite6; rc.13/rc.14 схему не меняют. Для отката до rc.12 необходим совместимый pre-v6 backup. RC30 переводит журнал в SQLite8: старые строки сохраняются, для повторных доставок добавляются канонические версии. Возврат к RC29 требует его пакета и backup базы до SQLite8.

### Удаление

Windows → «Установленные приложения» → Rele → «Удалить». Удаление останавливает свою задачу, убирает её, ярлыки, запись установленной программы и файлы приложения. `%LOCALAPPDATA%\Rele` сохраняется вместе с настройками и резервными копиями. Повторная установка использует эти данные. Если они больше не нужны, удалите именно этот каталог вручную после удаления приложения.

## Ubuntu Server

Из сессии владельца Codex:

```bash
sudo apt install ./rele-0.1.0-rc.26-linux-x64.deb
rele service status
```

Первичная установка использует `SUDO_USER`, если он передан и не равен root. При установке непосредственно из root / автоматизированного развёртывания пакет размещает программу, но не выбирает произвольного пользователя. Тогда достаточно:

```bash
sudo rele service install --user alice
```

`alice` — существующая учётная запись владельца Codex, пример. Служба systemd запускается при загрузке, работает после выхода из SSH и имеет `User=alice`. Она не требует `loginctl enable-linger`. Настройки службы хранятся в `/etc/rele/service.json` и собственном drop-in `rele-user.conf`; они содержат пути и имя пользователя, без токенов. Секреты остаются в закрытом пользовательском `config.json`.

Стандартные данные: `~/.local/state/rele`, профиль Codex: `~/.codex`. Для прежних нестандартных каталогов задайте их перед первым запуском:

```bash
sudo rele service install --user alice \
  --data-dir $HOME/state/rele \
  --codex-home $HOME/codex-profile \
  --port 3210
```

Установка в существующий профиль требует права пользователя на этот каталог. Изменение настроек уже установленной службы сначала останавливает её и создаёт backup прежних данных. Чтобы перенести содержимое в новый каталог, выполните отдельную процедуру восстановления; смена пути сама не переносит файлы.

Управление:

```bash
rele service status
sudo rele service stop
sudo rele service start
sudo rele service restart
sudo journalctl -u rele -n 50
rele backup
```

`rele status` проверяет готовность именно своего процесса через защищённый локальный API. `rele stop` штатно останавливает этот процесс; автозапуск systemd сохраняется. Указанный в `instance.json` чужой процесс не завершается по одному PID.

### Панель с рабочего компьютера

Сначала откройте SSH-туннель с рабочего компьютера:

```bash
ssh -L 3210:127.0.0.1:3210 alice@server
```

В этой серверной сессии выполните `rele open --print-url`. Откройте выданную ссылку в своём браузере в течение 60 секунд. Если локальный порт туннеля отличается от серверного, используйте ручной вход через `rele token` и локальный адрес выбранного порта. Открывать Rele на внешнем сетевом интерфейсе не требуется.

### Обновление и удаление

```bash
sudo apt install ./rele-НОВАЯ-ВЕРСИЯ-linux-x64.deb
sudo apt remove rele
```

При обновлении старая служба останавливается и прежний runtime создаёт SQLite backup вместе с конфигурацией. После замены активная служба запускается снова. Предварительно остановленная / отключённая служба сохраняет своё состояние. Повторная установка после удаления использует сохранённые настройки владельца и данные.

`apt remove` удаляет файлы программы и отключает службу, сохраняя её настройки для повторной установки. `apt purge` дополнительно удаляет принадлежащие пакету настройки службы. Обе команды сохраняют пользовательский каталог Rele. Его окончательное удаление — отдельное явное действие владельца.

Переход с прежнего `install-user-service.sh` отключает распознанную пользовательскую службу Rele, прежде чем запускать системную службу под тем же владельцем. Если прежний пользовательский manager не запущен, его запись отключается без обращения к неработающей сессии. Работающую вручную переносимую копию предварительно завершите через `Ctrl+C`.

## Общий Codex и переход с предыдущего RC

На новой установке выбрано «Общий Codex». На Windows достаточно установленного Codex Desktop: Rele запускает его штатный native backend напрямую, без скачивания CLI, копирования истории и адаптера между Desktop и сервером. Необходимые файлы выбранного native runtime сохраняются в рабочую копию Rele, чтобы обновление Desktop не удалило необходимые файлы. На Ubuntu используется native daemon установленного CLI. Поддерживаемые точные версии: 0.163.0, 0.163.0-alpha.10.2, 0.163.0-alpha.11, 0.163.0-alpha.11.2, 0.164.0-alpha.11.1, 0.165.0-alpha.1.2, 0.166.0-alpha.5.1, 0.166.0-alpha.6. Результаты совместимости конкретного commit и пакетов приведены в описании GitHub release. Непроверенные версии не получают разрешение на запись.

«Работающий сервер», «Выбрана версия» и «Новейшая найденная установка» — разные состояния. Автоматический выбор ищет максимальную поддерживаемую версию среди уже установленных; ручной выбор закрепляет конкретную установку. Сохранение выбора не заменяет работающий сервер. Переход выполняется отдельными действиями «Подготовить обновление» и «Обновить Codex» после завершения задач и закрытия остальных клиентов. На Linux управляемая замена проверена только между пакетами Codex 0.166.0-alpha.5.1; для alpha.6 она блокируется до замены процесса. Подключение к alpha.6 проверяется отдельно. Внешний сервер под другой службой требует управления через её владельца.

Rele не скачивает и не устанавливает пакеты Desktop/MSIX. Новый пакет может появиться в Windows Store позже, чем у другого пользователя. При ошибке установки `0x80073D02` одного закрытия Desktop может быть недостаточно: старый пакет может удерживать sandbox service. Используйте штатный механизм обновления Windows или пакета; Rele сам не завершает эту SYSTEM-службу ради установки.

Обычная загрузка Rele сохраняет явные WS/proxy/managed настройки. Выбранная задача Windows-установщика выполняет автоматический переход для безопасного локального случая по правилам rc.19 выше. Для нестандартного подключения можно явно выбрать «Общий Codex» в панели при отсутствии активных запросов. Пустое поле профиля наследует CODEX_HOME окружения либо штатный ~/.codex. Для нестандартного профиля задайте тот же абсолютный путь, что у Desktop. История и авторизация остаются в Codex; ID не копируются и не форкаются.

Для штатной установки ручные действия в панели не требуются. Если переход заблокирован чужими настройками или другим исходным профилем, сначала устраните названную причину. Для явного подключения после такой проверки остаётся кнопка «Подключить обычный Codex Desktop» в разделе «Codex». Она повторяет проверку через установленный launcher без переустановки и остановки Rele. При временном отказе запуска уже выбранного общего Codex ожидающая интеграция повторяется автоматически после его восстановления. Панель показывает записанное состояние интеграции и факт неудачной предыдущей проверки, отдельно от текущего соединения с сервером. Сырые сообщения установщика в панель не передаются.

Для смены сервера или профиля при включённой интеграции сначала нажмите «Отключить интеграцию Desktop», затем сохраните нужные параметры. Для нового shared target включите её снова отдельной кнопкой. Работающие окна и задачи не закрываются. После успешного включения дождитесь завершения задач, полностью выйдите из Desktop и откройте его обычным способом. Ранее выбранный отказ от интеграции сохраняется до явного включения.

Windows: установщик по умолчанию задаёт только пользовательский `CODEX_APP_SERVER_WS_URL`. Обычный запуск Desktop подключается прямо к общему native backend. Для перехода с уже открытого private stdio Desktop дождитесь завершения задач, один раз полностью выйдите через трей и откройте его обычным способом. Собственные прежние CLI_PATH/FORCE_CLI восстанавливаются по сохранённым данным; чужие настройки не перезаписываются. Выбор отключить интеграцию сохраняется при обновлении. Дополнительный ярлык задаёт тот же адрес дочернему Desktop, если родитель ещё использует старое окружение. Файлы Desktop не изменяются. Rele не копирует и не переписывает существующие профиль, историю и авторизацию; штатный backend продолжает собственные записи и может инициализировать отсутствующий профиль.

Windows-сервер слушает только `ws://127.0.0.1:PORT` без токена. Другие локальные процессы и пользователи этого ПК могут подключиться к нему. Это принятый предел локального RC; сетевой доступ не поддерживается. Порт сохраняется в установке и не заменяется случайным при восстановлении; неподтверждённый владелец занятого порта блокирует запуск, его процесс не завершается.

Общий Windows-сервер запускает отдельная задача `Rele-<SID>-Codex` под тем же пользователем с `InteractiveToken`/`LeastPrivilege`. Она не зависит от процесса gateway Rele. Контроллер сверяет владельца, executable/hash, время рождения процесса, профиль и PID владельца loopback-порта. Неизменяемый небольшой ProcessHost запускает native backend и ограничивает только его собственных потомков; Desktop соединяется с native сервером напрямую. Задача запускается при входе и повторяет проверку раз в минуту с IgnoreNew: работающий экземпляр сохраняется, завершившийся запускается снова без gateway Rele. Остановка или обновление Rele сохраняет работающий общий сервер. Удаление отменяет будущий автозапуск и восстанавливает собственный адрес Desktop, сохраняя текущий сервер и его клиентов.

Ubuntu Server: .deb включает отдельный owner-bound rele-codex.timer с oneshot starter вне rele.service cgroup. Он запускается при boot и восстанавливает отсутствующий daemon. GUI и пользовательская D-Bus сессия не требуются. Обычные `codex` и `codex resume ID` в стандартном интерактивном режиме сами используют штатный daemon. Запускайте CLI под владельцем Rele с тем же CODEX_HOME; команда Codex и файлы shell/profile не подменяются. В проверяемых версиях native `daemon_auto_start` включён по умолчанию. Явные `--no-daemon`, `--oss`, `--profile`, некоторые startup overrides и отключение `daemon_auto_start` меняют штатный выбор runtime; предупреждение CLI о работе без общего сервера нельзя игнорировать. Для строгого подключения остаются `rele codex resume ID` и `rele-codex resume ID` с явным native --remote. `codex exec` в этих версиях --remote не поддерживает.

Остановка, обновление и удаление самого Rele не вызывают native daemon stop и не обрывают другие клиенты. Отдельное управляемое обновление Codex заменяет только подтверждённый собственный сервер после проверки простоя и закрытых клиентов. После перезапуска Rele заново проверяет тот же сервер и сверяет потерянное подтверждение по UUID, без повторной отправки. Если Stop приостановил native-очередь, Rele автоматически продолжает только единственный подтверждённый собственный запрос; чужая или смешанная очередь требует явной проверки. Для отдельного private owned сервера оставлен дополнительный режим «Сервер Rele».

После подтверждённого подключения Windows выполняет native `codex-postflight`: удаляются только проверенные ненужные собственные остатки. Текущие и используемые пути, recovery references, профиль, история и авторизация сохраняются; неизвестное остаётся с причиной. Итог доступен в технических сведениях панели. Это не общая очистка установок Codex: Inno сам удаляет свой временный каталог, а dpkg заменяет прежний payload Rele.

## Вход и сохранность данных

Открытие через приложение создаёт случайную одноразовую ссылку на 60 секунд. Постоянный ключ панели не помещается в URL. Интерфейс немедленно удаляет фрагмент ссылки, меняет его на ключ через локальный API и хранит ключ только в текущей вкладке. Использованная / истёкшая ссылка возвращает к ручному входу; повторное открытие Rele создаёт новую.

При восстановлении не смешивайте SQLite с прежними файлами `-wal` / `-shm`. Подробная процедура и работа с неопределёнными доставками: [эксплуатация](OPERATIONS.md). Установка и обновление Rele не восстанавливают историю Codex или файлы проектов.
