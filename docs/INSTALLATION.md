# Установка, обновление и удаление

Рекомендуемые пакеты выпуска `0.1.0-rc.3`:

| Система | Файл | Файлы программы | Фоновый запуск |
| --- | --- | --- | --- |
| Windows x64 | `rele-0.1.0-rc.3-windows-x64-setup.exe` | `%LOCALAPPDATA%\Programs\Rele` | Задача текущего пользователя при входе Windows |
| Ubuntu Server x64 | `rele-0.1.0-rc.3-linux-x64.deb` | `/opt/rele`, команда `/usr/bin/rele` | Служба systemd `rele.service` под владельцем Codex |

Пакеты включают Node.js 24.19.0 и зависимости Rele. Пользователю не нужен npm. Codex устанавливается отдельно; Windows Rele использует доступный установленный backend Desktop или CLI. Для локальных голосовых отдельно нужны Python и модель. WSL не используется.

Скачивайте пакет и соответствующий `.sha256` из одного выпуска [GitHub Releases](https://github.com/smart-tinker/rele/releases). Windows: `Get-FileHash -Algorithm SHA256 <пакет>`. Ubuntu: `sha256sum -c <пакет>.sha256`. RC пока не подписан сертификатом Windows и не распространяется через APT-репозиторий. Обновление выполняется запуском нового установщика или установкой нового `.deb`; скрытого фонового скачивания обновлений нет.

## Windows

Запустите Setup под своей обычной учётной записью Codex Desktop. Администраторская установка и отдельная учётная запись SYSTEM не требуются. Мастер сам размещает файлы, создаёт запись удаления, ярлыки и фоновую задачу. На последнем шаге открывается панель в браузере.

В «Пуск» доступны:

- **Открыть Rele** — запускает фоновую задачу, дожидается готовности и открывает панель.
- **Перезапустить Rele** — штатно останавливает текущий Rele, запускает задачу заново и открывает панель.
- **Остановить Rele** — завершает текущий процесс. При следующем входе в Windows автозапуск остаётся включён.

Задача `Rele-<SID текущего пользователя>` использует `InteractiveToken` и `LeastPrivilege`. Она работает в сессии пользователя, сохраняет доступ к профилю Codex и DPAPI, повторяет запуск при сбое. После выхода пользователя процесс завершается; следующий вход запускает его снова. Для постоянного сервера без пользовательской сессии предназначен вариант Ubuntu Server.

Нативный `Rele.exe` запускает комплектный Node напрямую. CMD / PowerShell launcher не участвует в обычном открытии установленного приложения. Журнал: `%LOCALAPPDATA%\Rele\logs\service.log`; ротация ограничивает размер файла. Данные и резервные копии находятся отдельно от программы.

### Переход с ZIP

Если переносимый Rele ещё работает в PowerShell, завершите его через `Ctrl+C` перед установкой. Установщик не останавливает процессы из другой папки автоматически. Стандартный каталог `%LOCALAPPDATA%\Rele` подхватывается вместе с настройками, токенами и связками. Повторный ввод ключей при той же учётной записи и машине не требуется.

Прежний Startup launcher, созданный `install-autostart.cmd`, переносится автоматически: установщик проверяет его точный формат, прежний пакет и каталог данных. После успешного запуска новой задачи исходный скрипт сохраняется в `backups/legacy-startup-...` и убирается из автозапуска. Если файл был изменён вручную или относится к другому профилю, установка остановится с объяснением; такой скрипт не удаляется автоматически.

### Обновление

Запустите Setup новой версии под тем же пользователем. Установщик использует прежнюю папку программы и тот же каталог данных. До замены он останавливает собственную фоновую задачу, дожидается завершения и создаёт резервную копию с помощью прежнего runtime в `Rele\backups`. Ошибка остановки или backup прерывает замену файлов. После установки задача запускается заново.

Резервная копия — способ отката данных, а не обещание автоматического отката ОС при аварийном выключении. При смене схемы SQLite для возврата старой версии нужны и старый пакет, и соответствующий backup. В rc.3 схема остаётся v3, как в rc.2.

### Удаление

Windows → «Установленные приложения» → Rele → «Удалить». Удаление останавливает свою задачу, убирает её, ярлыки, запись установленной программы и файлы приложения. `%LOCALAPPDATA%\Rele` сохраняется вместе с настройками и резервными копиями. Повторная установка использует эти данные. Если они больше не нужны, удалите именно этот каталог вручную после удаления приложения.

## Ubuntu Server

Из сессии владельца Codex:

```bash
sudo apt install ./rele-0.1.0-rc.3-linux-x64.deb
rele service status
```

Первичная установка использует `SUDO_USER`, если он передан и не равен root. При установке непосредственно из root / автоматизированного развёртывания пакет размещает программу, но не выбирает произвольного пользователя. Тогда достаточно:

```bash
sudo rele service install --user alice
```

`alice` — существующая учётная запись владельца Codex, пример. Служба systemd запускается при загрузке, работает после выхода из SSH и имеет `User=alice`. Она не требует `loginctl enable-linger`. Настройки службы хранятся в `/etc/rele/service.json` и собственном drop-in `rele-user.conf`; они содержат пути и имя пользователя, без токенов. Секреты остаются в закрытом пользовательском `config.json`.

Стандартные данные: `~/.local/state/rele`, профиль Codex: `~/.codex`. Для прежних нестандартных каталогов задайте их перед первым запуском:

```bash
sudo rele service install --user alice \
  --data-dir $HOME/state/rele \
  --codex-home $HOME/codex-profile \
  --port 3210
```

Установка в существующий профиль требует права пользователя на этот каталог. Изменение настроек уже установленной службы сначала останавливает её и создаёт backup прежних данных. Чтобы перенести содержимое в новый каталог, выполните отдельную процедуру восстановления; смена пути сама не переносит файлы.

Управление:

```bash
rele service status
sudo rele service stop
sudo rele service start
sudo rele service restart
sudo journalctl -u rele -n 50
rele backup
```

`rele status` проверяет готовность именно своего процесса через защищённый локальный API. `rele stop` штатно останавливает этот процесс; автозапуск systemd сохраняется. Указанный в `instance.json` чужой процесс не завершается по одному PID.

### Панель с рабочего компьютера

Сначала откройте SSH-туннель с рабочего компьютера:

```bash
ssh -L 3210:127.0.0.1:3210 alice@server
```

В этой серверной сессии выполните `rele open --print-url`. Откройте выданную ссылку в своём браузере в течение 60 секунд. Если локальный порт туннеля отличается от серверного, используйте ручной вход через `rele token` и локальный адрес выбранного порта. Открывать Rele на внешнем сетевом интерфейсе не требуется.

### Обновление и удаление

```bash
sudo apt install ./rele-НОВАЯ-ВЕРСИЯ-linux-x64.deb
sudo apt remove rele
```

При обновлении старая служба останавливается и прежний runtime создаёт SQLite backup вместе с конфигурацией. После замены активная служба запускается снова. Предварительно остановленная / отключённая служба сохраняет своё состояние. Повторная установка после удаления использует сохранённые настройки владельца и данные.

`apt remove` удаляет файлы программы и отключает службу, сохраняя её настройки для повторной установки. `apt purge` дополнительно удаляет принадлежащие пакету настройки службы. Обе команды сохраняют пользовательский каталог Rele. Его окончательное удаление — отдельное явное действие владельца.

Переход с прежнего `install-user-service.sh` отключает распознанную пользовательскую службу Rele, прежде чем запускать системную службу под тем же владельцем. Если прежний пользовательский manager не запущен, его запись отключается без обращения к неработающей сессии. Работающую вручную переносимую копию предварительно завершите через `Ctrl+C`.

## Поиск Codex

В разделе «Подключения» включён режим «Находить Codex автоматически». На Windows Rele читает ограниченные сведения о своих серверных процессах Codex, пакетах Windows и известных местах установки; затем проверяет CLI командой `--version`. Графический launcher Desktop не запускается как CLI. Полные командные строки, история и токены Codex в диагностику не попадают.

Панель показывает имя варианта, путь, источник, версию CLI и возможный локальный адрес. Если доступных серверов несколько, выберите нужный явно. Версия подключённого app-server показывается отдельно: совместимость нельзя определить только по установленному CLI.

Desktop может запускать внутренний app-server через stdio и не открывать совместный сокет / WebSocket. Тогда Rele найдёт установку и объяснит, почему внешнее подключение недоступно. Установка программы сама по себе не включает общий транспорт Desktop и не создаёт второй сервер. Приёмка настоящего Desktop остаётся отдельным условием стабильного релиза.

## Вход и сохранность данных

Открытие через приложение создаёт случайную одноразовую ссылку на 60 секунд. Постоянный ключ панели не помещается в URL. Интерфейс немедленно удаляет фрагмент ссылки, меняет его на ключ через локальный API и хранит ключ только в текущей вкладке. Использованная / истёкшая ссылка возвращает к ручному входу; повторное открытие Rele создаёт новую.

При восстановлении не смешивайте SQLite с прежними файлами `-wal` / `-shm`. Подробная процедура и работа с неопределёнными доставками: [эксплуатация](OPERATIONS.md). Установка и обновление Rele не восстанавливают историю Codex или файлы проектов.
