# Rele 0.1.0-rc.23

Начальная инструкция Rele передаётся отдельным видимым сообщением и самостоятельным ходом Codex. Перед продолжением через Rele она один раз подтверждается для пары «фактический профиль Codex + исходный тред». Ожидаемый ответ — точный `NOREPLY`; обычные запросы и пассивный контекст ждут первого успешного подтверждения. Состояние сохраняется после перезапуска Rele. Без связанного источника автоматическая отправка не выполняется.

В деталях источника на странице «Связи» добавлена кнопка **«Послать первичное сообщение»** для явного повторения инструкции. Повторное нажатие во время известной ожидающей операции не создаёт второй ход. Неподтверждённая отправка или запуск сначала сверяются по прежнему UUID; слепого повторения нет. Ошибка и неожиданный ответ не считаются успешной инициализацией. Неудачный ручной повтор не отменяет ранее подтверждённую инструкцию.

Последующие входящие запросы содержат заголовок источника, автора, снимок известных участников и полный исходный текст. Общая инструкция больше не повторяется перед каждым запросом. Формат уже сохранённых пассивных записей и их квитанции не переписываются.

Новое сообщение из того же обсуждения Slack или темы Telegram может дополнить исходный выполняющийся ход Rele через штатный `turn/steer`. Это относится и к сообщениям других агентов в пределах действующего доступа. Сообщения из других источников остаются в очереди; активный ход Desktop не становится целью дополнения Rele. Перед отправкой проверяется тот же исходный ход, а потерянный ACK сверяется без повторного ввода. Ответ, Stop, подтверждения и уточнения остаются у первоначального управляющего запроса; дополнение не создаёт отдельного управления задачей.

Режим доступа меняется сразу выпадающим списком в строке таблицы «Связи»: **«Выключено»**, **«По упоминанию»**, **«Все сообщения»**. В личных чатах переключение сохраняет список разрешённых людей. Если список ещё пуст, Rele просит выбрать хотя бы одного человека; боты в личном списке не допускаются.

Для Slack добавлены штатные карточки выполнения и плана: `task_card` и `plan`. В исходное обсуждение передаются только публичные комментарии Codex и шаги плана собственного запроса Rele. Закрытые рассуждения и сырые события инструментов не передаются. Карточки не строятся из команд и их вывода. Уже подтверждённая карточка обновляется; неизвестный результат первой публикации не вызывает создания дубликата.

Схема базы Rele остаётся v7; состояние инициализации и дополнений хранится в существующем журнале метаданных. Профиль, ID и хранилище разговоров Codex не переносятся и не переписываются. Сохраняются прямое подключение Desktop к общему native WebSocket и независимый от gateway Windows owner.

Проверки точного commit и пакетов приводятся в GitHub release. Реальная приёмка карточек и доставки в Slack/Telegram, управление с телефона, перезагрузка ОС и длительная эксплуатация остаются отдельными проверками. RC не объявляет исправленными ранее наблюдавшиеся аварии native backend. Ограничения экспериментального native API, локального WebSocket без токена и неподписанного Windows RC сохраняются.
