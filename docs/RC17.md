# Rele 0.1.0-rc.17

Исправлены два отказа общего Codex на Windows.

После остановки daemon Windows может сохранять AF_UNIX сокет, для которого Node возвращает EACCES при чтении метаданных через stat/lstat, хотя проверка существования проходит. Rele теперь проверяет существование сокета, после чего штатный идемпотентный запуск Codex восстанавливает daemon. Ошибки доступа не трактуются как наличие сокета; проверки владельца, профиля и версии сохраняются. Запасной сервер не запускается.

При обычном запуске Desktop передаёт точный локальный параметр `features.prefer_mxc=true`. Адаптер теперь принимает его по правилам штатного общего подключения Desktop через WebSocket: backend песочницы Windows определяют общий профиль Codex и обязательные managed requirements. Он может отличаться от backend отдельного private-сервера Desktop. Адаптер не включает функцию, не меняет профиль и не перезапускает daemon. Значения false, кавычки, пробелы, неизвестные параметры, URL и обязательные sandbox overrides по-прежнему отклоняются; эффективный `code_mode_host` проверяется отдельно.

На тестовой Windows VM кандидатный адаптер открыл авторизованный Desktop обычным запуском через AppsFolder. В исходном чате выполнен ход Desktop, затем запрос через production Engine Rele: ответ сохранил контекст Desktop, получил native receipt и одну синтетическую доставку. То же окно Desktop показало запрос и ответ Rele; исходный ID и PID daemon сохранились. Реальный Slack/Telegram не настраивался, входящий запрос установленной службы не проверен.

Результат проверки кандидатного адаптера не заменяет приёмку готовых пакетов; результаты их проверки указываются в публикации выпуска. Поддерживаемые версии Codex, схема данных и правила сохранения истории не меняются; новых зависимостей нет.
