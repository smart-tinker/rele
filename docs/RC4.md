# Rele 0.1.0-rc.4

## Что изменилось

Основной режим **«Сервер Rele»** запускает собственный Codex app-server и управляет его жизненным циклом. Desktop можно закрыть. Установка Codex и его существующий профиль остаются источником авторизации, настроек и истории. На Windows Rele работает в сессии владельца профиля; на Ubuntu Server — как systemd-служба под этим владельцем.

Чат Codex в связке остаётся исходным чатом с прежним ID. Rele загружает каталог с названиями и продолжает выбранный threadId. Ошибка возобновления не приводит к копированию истории, fork или созданию нового чата.

Если другой процесс Codex удерживает право записи в тред, запрос сохраняется в очереди Rele с пояснением и повторяет попытку открытия через пять секунд. После освобождения Rele продолжает исходный запрос. Ответ получает только его источник: Slack или Telegram. Неподтверждённую постановку в очередь Codex Rele повторно не отправляет.

После терминального состояния и сверки ответа Rele освобождает тред и ждёт подтверждённого закрытия. Его app-server при этом продолжает работать. Другой процесс Codex может открыть тот же ID с обновлённой сохранённой историей. Следующий запрос Rele ждёт завершения освобождения предыдущего треда.

Автопоиск больше не требует доступного сокета Desktop для managed-режима. Он проверяет установленные backend/CLI, в том числе Windows `OpenAI\Codex\bin\<версия>\codex.exe`. Проверенные версии рекомендуются первыми. Явно выбранные непроверенные версии допускают просмотр каталога; запись блокируется.

В собственном сервере Rele не разрешает неподдержанное интерактивное действие и не предлагает подтвердить его в другом процессе Desktop. Такое действие получает явный отказ. Обычные подтверждения команд, изменения файлов и уточнения по-прежнему проходят через исходный канал или локальную панель.

## Обновление с rc.3

1. Установите новый Windows Setup либо `.deb` поверх прежней версии. Установщик сохраняет данные, токены и связки, создаёт резервную копию Rele и перезапускает его.
2. Откройте **«Codex» → «Сервер Rele»**. Сохранённые proxy / WebSocket подключения не переключаются автоматически.
3. Выберите рекомендованную установленную версию Codex. Проверенные версии этого выпуска: **0.163.0** и **0.163.0-alpha.10.2**.
4. Проверьте профиль. Пустое поле наследует `CODEX_HOME` окружения Rele или стандартный профиль текущего пользователя. Для нестандартного профиля Desktop укажите его полный путь.
5. Сохраните настройки и загрузите разговоры. Существующие связки продолжают использовать прежние ID; пересоздавать их не требуется.

Если тред остаётся занят, другой Codex ещё не освободил его. Завершение ответа в его окне не обязательно освобождает право записи. Закройте Desktop при необходимости и дождитесь завершения его процесса; Rele не останавливает его самостоятельно.

## Установка, остановка и удаление

Windows: `rele-0.1.0-rc.4-windows-x64-setup.exe`, стандартная пользовательская установка, ярлыки «Открыть», «Перезапустить», «Остановить Rele». Задача запускается при входе пользователя. Выход из Windows завершает её; работа до входа пользователя этим установщиком не обещается.

Ubuntu Server: `sudo apt install ./rele-0.1.0-rc.4-linux-x64.deb`. Служба работает после выхода из SSH и запускается при загрузке. Панель доступна через SSH-туннель на loopback.

Остановка и перезапуск Rele дожидаются завершения его собственного дочернего Codex. Сторонний Desktop / CLI не завершается. Удаление программы сохраняет данные Rele и не удаляет профиль Codex. Схема SQLite Rele остаётся v3.

Полная инструкция: [INSTALLATION.md](INSTALLATION.md). Резервное копирование и восстановление: [OPERATIONS.md](OPERATIONS.md). Backup Rele не включает историю Codex и файлы проектов.

## Что проверяет выпуск

Native CI Windows и Ubuntu выполняет проверки типов, модульные и API-сценарии, браузерные проверки, production UI smoke, сборку переносимых архивов и настоящий цикл установки, перезапуска, обновления и удаления обоих установщиков.

Для каждой из двух точных версий Codex запускаются два протокольных сценария:

- Внешний app-server: очередь, отдельные ходы, UUID корреляции, подтверждения, защита от смешанного ответа, восстановление без повторной постановки и proxy к существующему процессу.
- Собственный сервер Rele: реальный движок с SQLite, чтение исходного названного чата, ожидание чужого writer, контекст между двумя процессами, адресная доставка тестовых Slack / Telegram ответов, освобождение треда, перезапуск и подтверждённая остановка дочернего процесса. Проверяется, что пользовательская конфигурация не переписана и private-профиль не появился.

Эти сценарии используют изолированные профили и локальный тестовый provider. Они не обращаются к реальной модели, аккаунту, Telegram или Slack. Результаты хранятся в артефактах GitHub Actions соответствующего commit.

## Оставшаяся приёмка

Общая сохранённая история не доказывает мгновенное обновление уже открытого окна Codex Desktop. Требуется проверить на пользовательской Windows-установке, как Desktop освобождает тред, когда перечитывает историю и как отображает продолжение Rele. Доступ к приватному stdio Desktop для нового режима не требуется.

Настоящие разрешённые чаты Telegram / Slack и реальный Desktop проверяются отдельно по [ACCEPTANCE.md](ACCEPTANCE.md). Поэтому выпуск остаётся неподписанным release candidate. Автопубликация stable запрещена до выполнения этих сценариев.
